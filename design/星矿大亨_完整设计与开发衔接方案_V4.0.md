## 0. 使用规则：先承接进度，再补齐系统

### 0.1 三类信息必须分开

| 标记 | 含义 | 使用方法 |
|---|---|---|
| 规则基线 | 当前建议采用的玩法和边界 | 修改时记录原因与受影响模块 |
| 调参起点 | 费用、容量、时长、概率等示例 | 允许调整，统一从配置读取 |
| 体验目标 | 时长、决策密度、操作负担等预期 | 通过试玩确认，不能当作已验证事实 |

本文给出完整方向，并不意味着所有章节都进入下一次开发。

### 0.2 已有项目的处理原则

1. 能运行且不冲突的功能继续保留。
2. 先建立“本文规则—现有代码—差异—下一步”的映射，再修改实现。
3. 优先复用现有场景、美术、交互、生成器和数据结构，通过适配层补齐规则。
4. 不因为本文列出了模块名称，就批量重命名文件或把项目重写成同样目录。
5. 先备份当前存档并保留可运行版本，再做影响经济、世界状态和存档的改动。
6. 已在其他引擎或语言中开发的项目，先沿用现状；本文以 Godot 为默认技术方向，不自动触发迁移。
7. 已做但尚未需要的功能可放到实验开关之后，不把它们变成主线强制学习内容。
8. 每一轮只完成一个可试玩的改进，并记录前后行为。

### 0.3 规则冲突时的处理顺序

用户当前明确决定 > 已确认的项目约束 > 本文规则基线 > 本文示例数值。

实际代码与本文冲突时，先判断是否影响产品目标，再选择保留、适配或替换。不能把“与文档不同”直接等同于“代码错误”。

## 1. 产品定位与核心承诺

### 1.1 一句话定位

玩家经营一家边境矿业公司，在陌生星球发现矿藏、规划地下开采、建立火箭运输网络，通过投资和贸易逐步掌握一片星域的矿产生意。

### 1.2 玩家反复追求的体验

| 体验 | 直接表现 | 设计要求 |
|---|---|---|
| 发现 | 扫描揭开富矿、看到特殊地质 | 新信息能改变投资决定 |
| 开采 | 钻井到达矿床、采掘头运转、矿石进入仓库 | 地下结构影响路线与成本 |
| 运转 | 火箭自动装货起飞，矿场稳定生产 | 产能瓶颈清晰、自动化可靠 |
| 赚钱 | 发货交付、现金到账、投资回本 | 能解释钱从哪里来、花到哪里 |
| 扩张 | 新星球接入旧有网络，集团规模增长 | 已有资产持续有价值 |

### 1.3 产品边界

| 项目 | 本版基线 |
|---|---|
| 平台与模式 | PC 单人，持续世界，手动存档与自动存档 |
| 镜头 | 星图概览 + 横向二维矿场剖面，可使用有体积感的美术 |
| 时间 | 可暂停，可加速；退出游戏不计算离线收益 |
| 操作 | 鼠标为主，快捷键辅助；不需要手动驾驶飞船 |
| 策略来源 | 地质、资金、运力、交付地点、时机与投资回收周期 |
| 世界 | 破晓星域，原创星系与天体，不以太阳系为舞台 |
| 战斗 | 本产品主线不做战斗 |
| 建设链 | 基础设备通过现金采购；不加入多层制造配方 |
| 人员与生存 | 不做逐人生活、氧气食物、工人排班和满意度 |
| 航天 | 距离、运价、周期参与经营；不做真实轨道与燃料方程 |
| 长期目标 | 多种经营路线、可选终局目标、通关后继续经营 |

### 1.4 五条设计约束

- 新系统必须改变至少一种重要决定：去哪里、挖什么、怎么挖、怎么运、何时卖或何时扩张。
- 玩家扩大规模后，日常点击量不应随矿场数线性增长。
- 每项高收益机会都应有玩家能理解的代价。
- 明确区分“未知信息”与“规则没有解释清楚”。
- 不靠等待研究完成、反复搬矿场和堆叠地图数量凑时长。

## 2. 核心循环、时间与注意力

### 2.1 三个相互连接的循环

| 尺度 | 循环 | 玩家主要决定 |
|---|---|---|
| 矿场 | 扫描 → 规划 → 钻探 → 采掘 → 输送 | 下一笔建设费投在哪里 |
| 经营 | 装货 → 运输 → 交付 → 销售 → 回款 | 运力、库存和现金如何分配 |
| 集团 | 获取情报 → 评估机会 → 投资 → 稳定运行 → 扩张 | 哪个机会值得承担长期成本 |

成功销售的利润回到建设、船队、研究与新矿区。矿物也可交付给研究和终局工程，但始终有具体地点与库存。

### 2.2 时间基线

以下为调参起点，现有项目已有时钟时通过配置适配。

| 项目 | 初始设置 |
|---|---|
| 正常速度 | 30 秒现实时间 = 1 游戏日 |
| 加速 | 暂停、1×、2×、4× |
| 模拟步长 | 1/60 游戏日；1× 时约每 0.5 秒推进一步 |
| 市场报价更新 | 每个游戏日一次 |
| 财报周期 | 每 30 游戏日一次 |
| AI 战略评估 | 每 7 游戏日一次，事件触发可追加 |
| 自动存档 | 每 5 分钟现实游玩时间、完成重要交易前后；分槽轮换 |

时间倍率只改变每秒推进的模拟步数，不改变每步的经济公式。暂停时允许查看信息、规划和确认建设；施工、研究、货运、竞拍倒计时均停止。

模拟卡顿时不丢失经济步。可降低实际加速效果并显示“模拟速度受限”，不能跳过产量、费用或货物。

### 2.3 操作负担目标

- 初期主要操作当前矿场。
- 中期主要规划新矿场、分配船只、选择合同。
- 后期重点处理扩张、航线、中转和大型订单。
- 正常运行的旧矿场不需要每天确认生产、发射或销售。
- 集团总览按影响大小列出需要关注的事项；不要求玩家逐矿巡检。
- 不强制规定玩家必须把 50% 时间放在采矿界面。注意力应随集团成长转移。

## 3. 世界、规模与星图

### 3.1 世界设定

破晓星域由已开发边境与大片未充分勘探区域组成。公司从晨曦贸易港附近起步，持有初始矿区许可、一艘轻型运矿船，以及一笔有限资金。

政府和商业组织负责许可证、贸易港及已确认航道。竞争财团争夺矿区和订单。故事通过勘探记录、星球环境、商业新闻与重大工程呈现，不依赖大量对白。

公司处境是“资产老旧、现金有限、需要找到新机会”，标准模式不设置必须立刻偿还的开局巨债。

### 3.2 数据四层，操作三个主要界面

世界数据保留星域、恒星系、星球、矿区四层。操作集中于：

1. **星图**：缩放浏览恒星系和星球；选择天体时侧栏显示矿区、特性、航线和开发成本。
2. **矿场**：地表与地下剖面；扫描、建设、生产与起降。
3. **集团总览**：矿场、船队、库存、合同、研究与财务。

星球概览默认是星图中的信息面板；可以从告警或合同直接跳转目标矿场，不要求每次经过全部层级。

### 3.3 内容规模分层

| 阶段 | 内容规模目标 | 目的 |
|---|---|---|
| 核心验证 | 2 个矿区，位于 2 颗星球；1 个贸易港 | 验证重复开矿是否产生新决定 |
| 完整试玩 | 1 个恒星系、3 颗可经营星球、2 个贸易港 | 验证集团调度与扩张 |
| 首发内容候选 | 3 个星团、8–12 个恒星系、12–18 颗可经营天体 | 在可控制作量内验证长期经营 |
| 完整世界扩展 | 5 个星团、25–35 个恒星系、60–100 颗可探索天体 | 其中部分是信息点、遗迹、港口或景观，不全部建设矿场 |

“首发内容候选”不是降低长期定位，而是先确认单位内容的经营深度。30–50 小时是完整战役愿景；试玩不支持时，应补充有区别的经营情境，再决定是否增加内容数量。

### 3.4 五个星团的经营差异

每颗星球最多两个显著环境特性；作用必须在开发预览中说明。

| 星团 | 主体验 | 典型特性 | 有意义的应对 |
|---|---|---|---|
| 晨曦边境 | 学会稳定经营 | 近港、浅层矿、基础设施成熟 | 小额投资、快速回款 |
| 赤沙星群 | 钻探路线与回本 | 硬岩夹层、集中深矿 | 绕行、升级钻头或分期建设 |
| 霜环星群 | 勘探可信度与开发顺序 | 部分扫描模糊、可观深层储量 | 先详勘、分阶段投入 |
| 熔心星群 | 有限地表位置下的集约开采 | 建设槽位少、富矿集中 | 共用主井、提升主干运力 |
| 幽光深域 | 远距离高价值贸易 | 航程长、稀有资源、特殊订单 | 中转、储备运力、签约交付 |

高重力等特性主要体现为明确的运输费用系数，不新增一套燃料物品。环境风险不导致无预兆的整座基地毁灭。

### 3.5 航路与程序生成

- 航路是带权图，边包含旅行长度、通行费和事件状态。
- 普通飞船沿已确认航路移动，不模拟真实轨道。
- 起始区域保证连接主港及至少一个可行扩张机会。
- 重要资源存在多种可达来源，避免单个 AI 抢走唯一科技前置矿。
- 使用区域模板约束资源分布，再在模板内随机矿体与航路。
- 手工特殊天体通过模板嵌入，保留明确的发现价值。
- 已揭示的矿藏、报价事件与拍卖结果不因重载存档重新抽取。

## 4. 探索、情报与采矿权

### 4.1 三级信息

| 阶段 | 已知内容 | 玩家行动 |
|---|---|---|
| 遥感资料 | 天体类型、航程区间、疑似矿种、两项以内特性 | 判断是否值得调查 |
| 轨道勘探 | 候选矿区、储量区间、地质难度、可信度 | 比较项目和准备资金 |
| 地面扫描 | 局部矿体边界、硬岩、可采单元与剩余量 | 规划具体钻探线路 |

情报卡使用“预计 8,000–12,000 吨，可信度中等”等范围，不把尚未确认的储量显示成精确事实。扫描后精度增加。

### 4.2 探索行动

前期由贸易港提供勘探服务：玩家选择目标、支付现金、等待报告，不额外管理一支探测船队。

后期科技降低成本、缩短时长或提高信息质量。可视上仍表现探测器飞行，但不新增舰队调度类型。

调参起点：近邻轨道勘探 2,000 Cr、2 游戏日；远域更高，受航程影响。新手任务提供一次免费近邻勘探。

### 4.3 发现者权益

- 自费首次调查未知矿区，获得 10 游戏日的排他评估期。
- 评估期内可按已公布的许可价格取得开放矿区；放弃后可转入公开供给。
- 原本公开挂牌的商业矿区正常拍卖，不因玩家补做勘探变为私有。
- 特殊发现允许提交资料换取固定奖励并放弃优先权；同一发现只能兑现一次。
- 所有期限在界面清楚显示，暂停时不推进。

这让探索本身有收益，避免“玩家付钱找矿，AI 无成本立即抢走”。

### 4.4 权利类型

| 类型 | 获取方式 | 基线规则 |
|---|---|---|
| 初始矿区 | 开局持有 | 永久开采许可，不需要周期续费 |
| 开放矿区 | 现金购买许可 | 购买前显示基础开发与物流条件 |
| 商业矿区 | 竞拍许可 | 资金约束、退出自由、无无限加价 |
| 特殊矿区 | 发现或工程解锁后购买 | 附带独特地质或交付目标 |

许可证首版为长期持有，不同时加入到期、续租和自动失效。空置许可可有小额、明确的日费用，防止无成本囤地；起始许可免该项费用。

### 4.5 竞拍规则

公开估值范围、勘探可信度、最低价、截止时间和最小加价幅度。最高出价金额被冻结，失去领先后立即解除冻结；成交时才扣款。

关闭界面不等于放弃已提交的出价。玩家可设置最高自动出价，但系统不得超过上限。默认不在玩家未主动关注时弹出连续强制竞价窗口。

AI 只能根据其可获得的情报估值，不读取玩家专属的隐藏矿量。

## 5. 矿物、库存与建设资源

### 5.1 四种主要矿物

价格和成本均是原型调参起点，Cr 为游戏货币，t 为可销售矿石吨数。

| ID / 矿物 | 参考价 Cr/t | 采矿变动费 Cr/t | 经营角色 | 非销售用途 |
|---|---:|---:|---|---|
| iron_titanium / 铁钛矿 | 100 | 8 | 稳定、大宗、考验运力 | 基础工程和少量研究交付 |
| silicon_crystal / 晶硅矿 | 180 | 12 | 中值订单、交付时机 | 扫描、航电研究 |
| energy_crystal / 星能晶 | 420 | 25 | 低产量、高价值、远域经营 | 跃迁与高阶工程 |
| phase_ore / 异相矿 | 900 | 45 | 稀少、终局订单 | 深空工程 |

不引入独立科研点、工人点数和多种通用代币。研究使用现金和指定地点的样本交付。

矿物并非一级淘汰一级：基础矿的大宗需求持续存在；高价矿受到储量、采掘速度、投资额、距离及采购额度约束。

### 5.2 矿石计量

所有储量统一表示最终可销售矿物质量。地质中的品位影响单位时间可采量，首版不模拟废石实体、废渣库存与回收率生产链。

矿体外观可以有杂质，但不能把同一吨矿在“原矿”和“商品矿”两个口径间重复计量。

### 5.3 有地点的库存

库存只存在于明确位置：

- 矿区地表仓库。
- 船舱。
- 贸易港租用仓库。
- 中转仓库。
- 已交付工程或研究：从可用库存中消耗并记录用途。

集团顶部可以显示总库存，但必须能展开所在地。不能在甲星球扣除乙星球的本地库存。

库存的“可用、预留”是同一批物品的状态分类，不能把预留数量再加一次当作新库存。

### 5.4 建筑采购

普通钻机、仓库、飞船等采用现金采购，报价包含明确的交付费与交付时间。

- 订单确认时扣除购买费用。
- 到货后才可使用。
- 未发货订单取消可退 90%，已发货订单到货后按二手规则处理。
- 新手初始设备可立即交付，正式扩张设备按地点计算时间。
- 新设备交付采用外部供应商服务，不占玩家的运矿船；费用已计入报价。
- 玩家搬迁自己的旧设备则可占用运矿船载重，或支付外包搬迁费。

研究和特殊工程必须在目标港交付矿物，不能瞬间跨星球扣货。

### 5.5 库存预留

优先级为：玩家明确锁定的研究/工程与合同预留 → 普通自动出售。

预留失败时提示缺口，不自动挪用其他项目的货物。玩家可手动解除预留，但界面要提示受影响的交付。

## 6. 矿场结构、扫描与钻探

### 6.1 地图与表现

矿场采用横向地表 + 地下剖面。背景表现整颗星球的天空、地貌和远景；实际操作发生在有限矿区。

调参起点：96 × 48 个逻辑格，每格 5 米。视觉可以平滑绘制，不要求显示方格或逐格点击。

地图数据包含地形、岩层硬度、建设位置、矿体、已揭示区域和钻探网络。未知区域不显示真实矿体轮廓。

### 6.2 最少需要的设施

| 设施 | 作用 | 玩家操作 |
|---|---|---|
| 地质扫描 | 揭示一定范围内的矿体和岩层 | 点击扫描区域 |
| 地表钻井平台 | 提供地下入口与地表提升能力 | 选择地表位置 |
| 钻探线路 | 抵达矿床并输送矿石 | 指定目标，可添加绕行点 |
| 采掘头 | 开采附近已连通的矿体单元 | 放置或沿井道迁移 |
| 地表矿仓 | 缓冲产量与运输 | 扩容、设置库存预留 |
| 起降设施 | 船只装卸 | 初期与基地一体提供 |

基础供电、工人和维修已计入设备运营费用，首版不再画电网和生活设施。

### 6.3 扫描

- 基础扫描展示圆形或扇形区域，费用取决于扫描深度和范围。
- 首次教学扫描免费；后续基础扫描初值 300 Cr、范围半径 8 格。
- 同一区域重复扫描不会重新抽取矿体。
- 模糊信号表示存在矿化迹象，精确扫描后才能确认形状及估计储量。
- 规划经过未知区域时，线路显示费用区间；施工遇到已提示的不确定硬岩时停止并等待处理，不自行无限追加费用。
- 基础扫描至少能找出一条可回本的起始路线。

### 6.4 固体矿开采规则

钻探线路抵达矿床后，安装采掘头。采掘头只能开采其范围内、与作业点连通的已揭示矿体单元。

调参起点：采掘半径 4 格；穿过完整不可通行岩层的相邻矿体不视为连通。当前范围挖尽后，可以延伸井道、迁移采掘头或增设采掘头。

不会因为“碰到矿体边缘”，就把整张狭长矿体自动抽空。

同一矿体可被多个采掘头覆盖。服务器式权威模拟层统一分配每一步可采量，避免同一剩余矿量被多个头重复扣除。

### 6.5 路线规划

- 默认给出一条可施工的估算路线，玩家可添加拐点调整。
- 同屏展示总费用、预计施工时间、穿越岩层和预计可接入储量。
- 硬岩可采用绕行或升级钻头；无法施工的地层明确标色。
- 路线在确认前可取消或修改，不扣款。
- 确认施工时校验预算并扣款；不得允许资金不足的长路线先建后欠费。
- 路线改变矿体可达性，但不改变矿体既有位置和总储量。

已揭示地质使用确定报价。涉及未知地质的施工按玩家确认的预算上限预付，完工后退还未使用部分；触及预算上限或无法穿透的岩层即停工，不自动追加。取消未开工的井道工单全额退款；已经开工只退尚未使用的预算，已完成井道保留。这与设备采购的 90% 取消退款规则分开处理。

原型可仅支持水平/垂直或简化折线，后续再优化视觉。不需要自由曲线与真实钻头物理。

### 6.6 地下网络

首版每个地表钻井平台对应一棵地下输送树：主井、分支、采掘头。不同树可连接同一地表矿仓，但地下不做环形网络。

每条线路有输送容量；共享主干的多个采掘头共同占用容量。钻井平台有总提升上限。

地表设施到矿仓默认自动接驳，不要求额外画一套复杂地表运输带。若已有地表运输实现可保留，但先验证它是否提供必要决定。

### 6.7 停产与限产

矿仓满载或输送不足时，采掘头自动降低或暂停生产，不销毁矿石。停止生产后不扣按吨计费的采矿成本；固定维护费继续发生。

玩家可暂停采掘头、整台钻机或矿区。明确区分：

- 运行：按产量计费并支付固定费。
- 暂停：保留设备，固定维护降至 25% 的调参起点。
- 封存矿区：设备与数据保留、关闭生产，仅支付少量基地保留费。
- 搬迁/出售：设备从原址移除，井道保留但不能作为可售设备。

### 6.8 开采画面反馈

采掘头作业、矿石移动、地表堆料与火箭装载都可见，但这些粒子和动画是数据的表现，不是实际库存单位。

暂停或掉帧不会导致飞行中的装饰矿石变成丢失货物。

## 7. 矿场生命周期与设备价值

### 7.1 生命周期

勘探 → 初期开采 → 增设采掘头 → 达到稳定产能 → 局部矿体耗尽 → 深层扩展或周边开发 → 封存/搬迁。

单条矿脉耗尽不意味着整个星球立即失去价值。基地、许可和星港仍可服务同星球其他矿区。

### 7.2 三种继续经营方式

| 状况 | 可选方案 | 主要代价 |
|---|---|---|
| 当前采掘范围挖完 | 沿已有井道迁移采掘头 | 少量停工与搬迁费用 |
| 浅矿结束、深处仍有矿 | 新钻井或延伸主井 | 钻探投入、产能共享 |
| 本矿区缺少好机会 | 转到同星球邻近矿区或其他星球 | 许可、设备搬迁与运力占用 |

不做必须持续移动整个基地才能维持生存的强制循环。

### 7.3 回收与沉没成本

| 项目 | 默认处置规则 |
|---|---|
| 钻井平台、采掘头 | 可搬迁；二手出售初值为实际购置价的 60%，扣除明确费用 |
| 火箭 | 可改派航线或出售；售出前必须清空/转移货物 |
| 已钻井道 | 沉没成本，不按原价回收 |
| 矿仓设备 | 可回收，库存须先搬走或出售 |
| 起降基地土建 | 部分沉没成本；星球后续开发可继续使用 |
| 采矿许可 | 通过资产市场出售，价格依赖公开储量与条件，不保证即时成交 |

拆除涉及有货库存或已接船次时先给出解决方式，禁止静默删除物资。

### 7.4 衰减与预警

产量下降优先来自可采单元耗尽、采掘头停产和线路瓶颈；不额外给矿场加一个无法解释的全局衰减系数。

根据已知储量与当前配置估算剩余开采天数，未知深层储量单独显示。

预警初值：当前可采储量预计维持不足 15 天时黄色提示；不足 5 天时高优先级提示。扩大扫描或改变开采速度后重新计算。

### 7.5 成熟矿场管理

“自动经营”在本版的含义是按照现有设施和规则继续生产、运输、销售，不包含自动购买钻机和自动开拓未知区域。

玩家可以保存地表设施组合。地下路线不直接复制到不同地质；先预览碰撞、矿体接入与费用，再允许逐项应用。完整蓝图为后续便利功能，不阻塞基础经营。

## 8. 火箭运输与中转

### 8.1 船只承担的任务

玩家设置起点、终点、矿物、用途和船只数量。飞船自动往返；发射、飞行、到港与回收由动画表现，不需要驾驶。

初期只做矿区—贸易港直达航线。中期开放共享船池与优先级，后期开放中转。可视飞船在星图上的位置对应实际航程进度。

### 8.2 三种船型

以下为测试起点；船名、模型与现有资产可映射，不必重做。

| 参数 | 隼式轻型 | 游隼可回收中型 | 巨鲸重型 |
|---|---:|---:|---:|
| 购置价 Cr | 38,000 | 145,000 | 480,000 |
| 载重 t | 100 | 350 | 1,000 |
| 速度系数 | 1.0 | 0.9 | 0.7 |
| 装载时间/日 | 0.25 | 0.40 | 0.75 |
| 卸载时间/日 | 0.25 | 0.40 | 0.75 |
| 周转维护时间/日 | 0.50 | 0.70 | 1.50 |
| 每次往返固定费用 F | 400 | 700 | 1,800 |
| 每单位往返航程费用 k | 2,000 | 1,250 | 2,200 |
| 固定维护 Cr/日 | 40 | 180 | 650 |

对一条单程标准长度为 L 的对称直达航线：

- 满载无等待周期 T = 2L / 速度系数 + 装载时间 + 卸载时间 + 周转维护时间。
- 往返费用 K = F + 2L × k + 已显示的通行费与环境附加费。
- 估算满载运力 = 载重 / T。
- 实际运力还要扣除等货、排队、无法卸货及改派影响。

非对称路线分别加总去程与返程的边权和费用，不能直接使用 2L。

环境附加费首版按起点重力系数 G 计算为 F × (G - 1)，常规星球 G = 1，高重力示例 G = 1.3；只作用于固定发射项，不对全部费用重复乘系数。双向均有特殊起降费用时分别列账，不能隐藏在多个系数中重复收费。

界面通常只展示载重、预计周转、每趟费用和购买价。详细参数放在展开说明中。

### 8.3 船型选择的长期意义

轻型船适合试采、尾矿清运、小批量高价值资源和紧急合同。中型船适合稳定供货。重型船需要足够货源和港口处理能力，否则低装载率与高维护费会吞噬优势。

航线比较同时展示每吨成本、每船日贡献、初始投入和预计回本区间。不能仅按售价或船舱容量排序。

### 8.4 船只状态与费用

| 状态 | 发生的事 | 状态边界 |
|---|---|---|
| 等待任务 | 位于具体节点，等待分配 | 不会瞬移到矿区 |
| 前往装货点 | 执行调位航程 | 产生明确调位费与时间 |
| 等货 | 到达矿场，等待货量或截止条件 | 最大等待时间可触发部分装载 |
| 装货 | 锁定货物批次与数量 | 完成装载后从仓库转入船舱 |
| 去程 | 货物随船移动 | 出发后不直接改目的地 |
| 卸货 | 预留港口仓容并转移货物 | 完成后才算到港库存 |
| 周转维护 | 执行本趟维护 | 不能同时接另一任务 |
| 返程 | 按航线返回 | 在下一节点边界允许改派 |
| 阻塞 | 无钱开新趟、缺仓容或路线中断 | 原因可见，库存不会消失 |

每趟启动前校验并预付该趟已知费用，包含已约定返程。途中事件若追加费用超出预付范围，等待下一节点让玩家选择；不通过随机账单把已付费船只永久困在途中。

初次调位与正常往返分开计费，不能重复扣除同一段航程。事件影响和当次费用在发船记录里保存。

### 8.5 默认装货策略

默认规则为“尽量满载，但最多等 2 游戏日”，并增加：

- 矿区停止生产或本地可采资源耗尽时，清运剩余库存。
- 合同接近截止时，按预计到港时间提前发送已有预留货物。
- 有明确手动指令时允许立即部分装载。
- 不发送空载销售班次。
- 设置最小批量时，清尾货和紧急交付可以覆盖该条件。

仓库 70% 只能作为参考提示，不能成为唯一发船触发条件。

### 8.6 港口仓容与卸货

订立航线时校验目标港是否有仓储账户。船到港后先为本次卸载量预留空间，成功才开始卸载。

港仓不足时允许分批卸货；未卸部分留在船舱，船只显示“港仓不足”。不能悄悄销毁矿石，也不能将未卸货部分计为已交付。

在玩家开启“到港即售”且买方有额度时，可卸一部分、卖一部分、再继续卸载。没有买方额度时，船会等待或按预先批准的备用港规则转运。

### 8.7 共享船池

早期采用固定航线分船。共享船池在第三个经营点左右引入，基本策略：

1. 先处理预计会违约的已预留合同。
2. 再处理会导致明显停产的满仓矿区。
3. 再按预计单位船日贡献分配。
4. 为等待时间过长的可执行任务增加优先级，避免低优先级矿区永久饥饿。

已在途船不能同时分配给新任务。玩家可锁定最低保留运力，避免全部船只追逐同一种高价货。

### 8.8 中转星港

中转增加一次装卸、仓容占用和转运费，但可能通过“轻型支线汇货 + 重型干线”降低长途成本。

它不提供凭空缩短全部距离的万能效果。路线评估应同时考虑额外装卸时间、满载率、费用与交付期限。

若现有项目已做直接跨星系航行，可以继续使用；中转作为后续可选优化，不强迫把所有既有航线改造为多跳。

### 8.9 航路事件

航道干扰优先影响尚未出发的航次；在途航次按已确定的事件规则延迟或在下一个节点选择绕行。事件持续时间有区间提示。

标准难度不随机炸毁船只或清空全部货物。事件取消后，不自动清除玩家建立的有效替代路线。

## 9. 市场、销售与合同

### 9.1 每个贸易港具有独立需求

矿物到达某港，才能在那里交易。报价只代表当前成交价，预计到港价使用范围或趋势提示。

NPC 买方是经济系统的外部需求来源，其预算和购买额度由市场配置提供；竞争财团则有有限现金与库存，两者不能混为无限资金 AI。

首版玩家只开采并出售矿物，不开放常规买入后跨港倒卖，先减少套利与库存定价复杂度。

### 9.2 两类采购商

| 采购商 | 行为 | 玩家取舍 |
|---|---|---|
| 常规采购商 | 报价平滑、额度较大 | 稳定回款 |
| 临时高价采购商 | 额度较小、报价较高且期限明确 | 值得调货，但无法承接全部产量 |

起始港铁钛矿调参起点：常规买方每日 600 t，高价买方每日最多 100 t。其他矿种分别配置，不能按同一数量比例直接套用。

每日额度不跨日累计。两家都受明确额度约束，不能在同一天无限倾销而不影响需求。

### 9.3 动态参考价

建议采用可解释的供需模型，再做平滑，不使用纯白噪声价格。

示意公式，供给和需求均取同一港、同一矿种、同一 7 日窗口的吨数：

    imbalance = (demand_7d - delivered_supply_7d) / max(demand_7d, demand_floor)
    target = base_price × clamp(1 + 0.25 × imbalance + event_modifier, 0.70, 1.40)
    next_reference = 0.85 × old_reference + 0.15 × target

- delivered_supply 包括玩家和 AI 实际出售给买方的货物，不包括在途货物和未卖库存。
- demand_floor 防止新市场零需求导致除零。
- 普通买方对参考价做额外平滑，并使用约 0.95 的报价系数。
- 临时买方可使用约 1.10 的系数与有限额度。
- 0.70–1.40 约束的是参考价；买方最终报价仍可因系数不同而超出该区间，UI 应展示实际价格。
- 所有系数为调参起点，事件幅度与采购数量需要联合验证。

市场每天固定时间更新一次报价。当天成交按当日剩余额度与公布价格处理，市场供需反馈进入后续报价，不让同一帧内先后点击导致不可见的瞬时跌价。

### 9.4 销售策略

每个“港口 + 矿种”设置一个默认策略：

- **直接出售**：在当日有额度的买方中从高到低成交。
- **目标价出售**：达到最低价格时成交；未达到则保留。
- **优先交付**：先执行已预留的合同、工程和研究，再处理余货。

新增安全选项：港仓超过玩家设定比例或现金低于保底线时，提示是否启用应急出售。默认不替玩家擅自打破目标价格；玩家可事先明确授权自动应急销售。

仓储费用按实际持有吨数和经过的游戏时间结算，暂停时不收费。

### 9.5 囤货代价

- 港仓容量有限，更多仓容需要租赁。
- 持有矿物产生明确的吨日仓储费，初值 0.5 Cr/t/日。
- 占用现金，可能延后新矿开发。
- 价格未必按预期恢复。

不增加矿石腐烂或随机消失。囤货是否合理由价格、费用与机会成本决定。

### 9.6 合同字段

每份合同必须包含：合同 ID、发行方、矿种、目标吨数、交付港、固定价格、截止时间、保证金、未交付违约规则、已交付量、预留量与状态。

合同交付按“完成卸货并划拨给发行方”的时间认定，不按起飞或到港动画时间认定。

### 9.7 合同结算

- 接单冻结合同总额 10% 的现金作为保证金，仍属于资产但不可花费。
- 每次有效交付按固定价格立即支付相应货款。
- 完整交付后释放保证金。
- 到期未完成时，对未交付部分货值收取 10% 罚金，从保证金扣除并释放剩余。
- 已交付货物不再退回；未交付货物解除预留。
- 违约后该发行方 30 游戏日内不提供新合同。
- 初期最多同时进行 2 份合同；技术或经营许可可提升额度。
- 玩家主动取消使用同样的未交付结算规则，确认前展示金额。

起始示例：铁钛矿 500 t、固定价 125 Cr/t、交付港为晨曦港、期限 20 日；合同额 62,500 Cr、冻结保证金 6,250 Cr。实际是否能完成由现有产能和航线决定。

### 9.8 接单辅助

提供保守预计交付量、已预留库存、在途货物、缺口和最晚发船日。保守估算不将尚未勘探的矿量计入。

允许玩家在风险提示后承接有挑战的合同，但系统不能把明显缺少前置科技的合同作为唯一主线任务。

同一批矿物只能属于一项交付预留。合同交付后不能再出售或转交其他合同。

## 10. 财务、资金周转与经营恢复

### 10.1 主界面只突出少量指标

现金与冻结资金、当前矿场可采储量、实际产量、预计运力、当前位置报价。其他内容按需展开。

集团页面补充“预计现金可维持天数、未来 7 日交付、当前主要瓶颈”，帮助玩家决定下一步。

### 10.2 三种财务口径

| 指标 | 定义 | 用途 |
|---|---|---|
| 现金流 | 实际收付款，包含设备、许可、贷款和偿还 | 判断能否继续运转 |
| 经营结余 | 销售收入减采矿、运输、维护、仓储、利息等日常费用；不含资本支出 | 比较经营活动 |
| 估计净资产 | 现金、库存估值、可回收设备与许可估值，减债务和应付款 | 观察集团规模 |

首版不把经营结余标成完整会计净利润。若以后加入折旧与账面资产，单列“会计利润”，不要混用口径。

资金字段统一为：cash 表示公司持有的现金总额，reserved_cash 是其中被冻结的部分，可支配现金 = cash - reserved_cash。冻结和释放只改 reserved_cash，不制造收入或支出；实际成交、违约扣款等才改变 cash。净资产计算只计入一次 cash，不再额外加被冻结现金。

库存估值使用保守公开价并受流动性折扣约束，不能使用玩家自行设置的目标价抬高净资产。

### 10.3 支出与资金占用

- 一次性支出：许可、扫描、井道、设备、升级、研究、星港投入。
- 资金占用：合同保证金、竞拍冻结款；冻结本身不计为费用。
- 按产量：采矿变动费、可选精炼处理费。
- 按时间：设备维护、基地保留费、港口仓储费、贷款利息。
- 按运输：调位费、每趟费用、通行费、可选转运费。
- 条件发生：合同违约、明确展示的维修或改线费用。

每项费用必须有账本类型、对象 ID、时间和金额。

### 10.4 不同项目的比较

对新矿区显示：

- 获得许可与基本设备需要多少现金。
- 已知储量下的保守产能范围。
- 航线成本、港口需求和预计回款时长。
- 静态回本估计及其前提。
- 现有船只改派后的其他矿区损失。

不能只显示“预计收益 +300%”，而不说明时间和成本口径。

### 10.5 贷款

测试起点：可用总授信 = min(50,000 Cr, max(20,000 Cr, 合格抵押资产估值 × 30%))。剩余额度再减已借本金。

合格抵押资产排除借来的现金和冻结保证金，防止借款本身推高授信。库存采取保守折扣，临时高报价不能立刻无限提高额度。

利息初值为每 30 游戏日 2%，按天累计。允许随时还本金；不在无提示时自动扣光现金。授信不足无法借款，不创建隐形负现金。

### 10.6 现金不足时

1. 停止新的采购、扫描和新航次预付。
2. 已预付且在途的航次继续完成。
3. 按吨生产费用不足时降低产量，不能免费无限采矿。
4. 固定费用不足部分进入应付款并触发提示，不能静默制造无限欠款。
5. 首次进入严重短缺时自动暂停一次，提供出售库存、封存矿区、卖设备、借款等入口。
6. 应付款逾期 7 日后进入明确的重整期限，倒计时 30 游戏日；到期无法清偿才进入经营失败/重整选择。

标准模式允许一次主动债务重整：按公开清算规则变卖部分资产、清偿约定债务，保留已经发现的世界信息，重新以较小规模经营。重整不作为可反复领取现金的循环，也不免费保留全部资产。

新手起始资金、矿量和航程必须保证至少一条合理经营路径可行，但不保证任何错误投资都必然获利。

## 11. 原型参数、计算与核验例子

### 11.1 起始资产

调参起点：

- 可支配现金 30,000 Cr。
- 已持有初始矿区许可和基础起降设施。
- 地表矿仓 300 t。
- 已交付一艘轻型船，初始位于矿场。
- 晨曦港租用仓容 500 t。
- 免费教学扫描一次、免费近邻轨道勘探一次。
- 可发现浅层矿团不少于 1,800 t；周边经扩展可获得至少 6,000 t 总可行储量。
- 初期不设置到期债务和随机停航事件。

### 11.2 设施参数

| 项目 | 费用初值 | 能力或结果 | 固定维护/日 |
|---|---:|---|---:|
| 基础钻井平台 | 8,000 Cr | 总提升 60 t/日 | 50 Cr |
| 基础采掘头 | 2,000 Cr | 基础 40 t/日，半径 4 格 | 20 Cr |
| 软岩井道 | 100 Cr/格 | 基础输送 60 t/日 | 0.5 Cr/格 |
| 硬岩井道 | 300 Cr/格 | 需相应钻头，施工更慢 | 0.5 Cr/格 |
| 矿仓扩容 | 6,000 Cr | 增加 500 t | 10 Cr |
| 平台提升改造 | 9,000 Cr | 60 → 100 t/日 | 增加 20 Cr |
| 线路扩容 | 原线路费用的 60% | 60 → 120 t/日 | 增加原维护的 25% |
| 基地运行费 | 按日支付 | 包含基础供能等 | 60 Cr |

施工初值：软岩 8 格/日，硬岩 4 格/日；设备本地安装 0.5 日。并行施工能力先限制为每个平台一个作业任务，避免无限瞬间打井。

一条 24 格软岩线路，配一台平台和一只采掘头，建设费为 8,000 + 2,000 + 2,400 = 12,400 Cr。免费教学扫描之外若再扫一次，总投入为 12,700 Cr，起始余款 17,300 Cr。

该表用于跑通经济；起始资产具有教学补贴，不以首矿异常短的回本时间代表正式矿区投资收益。

### 11.3 采矿步进

对单采掘头 i，先计算本步潜在开采量：

    potential_i = min(基础速率 × 地质效率 × dt, 可达矿体本步可分配剩余量)

再按树形输送网络、平台提升能力、仓容和可支付的变动费用统一分配。共享矿体先按稳定排序及公平分配计算，避免更新顺序导致一个采掘头永久抢走全部矿。

在最终扣除矿体前，必须先确认：
- 线路与平台容量允许；
- 矿仓有空间；
- 变动费用可支付。

最终产量减少矿体储量，同时增加地表库存并扣除相应现金。不能先挖掉再因仓满丢弃。

所有速率都乘 dt。剩余储量与剩余仓容的单位是 t，不能与 t/日直接取最小值。

### 11.4 仓储与库存关系

    矿场库存变化 = 采矿入库 + 本地退货 - 装船完成转出
    船舱变化 = 装船完成转入 - 卸货完成转出
    港口库存变化 = 卸货转入 + 加工产出 - 销售 - 工程消耗 - 加工投入 - 转运装船

预留操作不改变物理库存总量；只改变可自由使用量。跨节点转移必须采用一次原子操作，不允许源扣了而目的未加，或两个地方同时拥有货物。

### 11.5 运输比较例子

仅比较满载情况下的销售额、采矿变动费与每趟飞行费，不包含矿场固定费用、船只维护和资本回收。

同一艘 100 t 轻型船：

| 项目 | 近港铁钛矿 | 远港晶硅矿 |
|---|---:|---:|
| 售价 | 100 Cr/t | 180 Cr/t |
| 采矿变动费 | 8 Cr/t | 12 Cr/t |
| 单程长度 L | 0.5 | 2.0 |
| 无等待往返周期 | 2 日 | 5 日 |
| 每趟费用 | 2,400 Cr | 8,400 Cr |
| 每趟贡献 | 6,800 Cr | 8,400 Cr |
| 每船日贡献 | 3,400 Cr | 1,680 Cr |

这说明高单价矿不一定更值得占用紧缺船只。实际决策还要计算装载率、矿量、建矿投资和合同价格。

### 11.6 仓库不是永久运力

日产 300 t、日均运力 200 t 时，净积压 100 t/日。增加 500 t 仓容，只增加约 5 日缓冲，不能解决长期产运缺口。

若产量即将回落、下一艘船即将交付或暂时等待高价，扩仓仍然合理。界面应明确显示这一前提。

### 11.7 调参顺序

先固定单位与结算规则 → 验证首矿可生存 → 调整首次回款节奏 → 验证第二种投资选择 → 加入第二矿种与距离 → 验证中期现金压力 → 最后调整科技与终局成本。

同一轮避免同时改矿价、船速、矿量、设备费和市场需求，否则难以判断哪项导致体验变化。

## 12. 研究、升级与资源用途

### 12.1 研究规则

研究由总部统一管理，一个研究槽位。费用在开始时扣除，所需样本先交付研究港并消耗。本版统一为：开始后可以暂停，不能取消或退款；暂停不产生额外研究费用。确认前必须显示总费用、样本和工期。

基础自动生产、自动往返、最低限度的财报与告警从开始就可用，不作为科技奖励。

关键资源在解锁其专用技术前，必须至少存在一种低效率但可行的获取方式，防止“需要星能晶研究才能进入所有星能晶产地”的循环依赖。

### 12.3 专精来自投资组合

不用增加职业选择或永久互斥科技树。玩家通过支出顺序形成：

- 勘探与深井投资较多：寻找高价值矿藏。
- 船队与仓储投资较多：做稳定大宗供应。
- 信息和履约资质投资较多：围绕订单调整产能。

所有路线可以转型，代价是时间与已经投入的资金。

### 12.4 科技资源的可达性保证

- 晶硅矿至少有一个初始恒星系内、基础设备可低效率开采的来源。
- 星能晶至少有一个在 L2 解锁跨系航行后即可抵达的来源，不以 E4、L4 或 L5 为前置。
- 异相矿至少有一个经 E5 调查、L5 航行与 M4 设备能力可开发的来源；M5 提高效率，不作为获取第一批异相矿的条件。
- 上述保底来源采用开放许可或可替代的公共机会，不能全部由 AI 一次性拍卖锁死。
- 生成地图后自动检查“所需资源可达性 + 科技前置”图，发现循环时更换模板，不靠玩家读攻略解决。

## 13. 竞争财团与商业行为

### 13.1 三个对手

| 财团 | 重点行为 | 可见影响 |
|---|---|---|
| 赤曜矿业 | 大宗矿区、扩大稳定产量 | 竞拍和基础矿供给 |
| 星环运输 | 航线与港口扩建 | 重要枢纽机会、运输服务竞争 |
| 银穹资本 | 高价订单与库存时机 | 合同竞争、阶段性卖货 |

第一完整试玩只启用一个 AI。完整版本再增加不同偏好的对手。

### 13.2 抽象模拟状态

AI 保留现金、已知情报、许可、抽象矿区剩余量、产能、库存、运力、在途货物、债务和投资计划。

不需要逐台模拟 AI 地下钻机，但必须遵守主要约束：

- 没钱不能无限出价。
- 没有矿量不能生产。
- 产量超过运力时会积压。
- 在途货物未到达不能销售。
- 合同交付消耗实际库存。
- 资产采购需要时间，不能刚竞拍完立刻全额投产。

### 13.3 决策节奏与可解释性

每 7 日进行一次常规战略评估，竞拍和合同事件单独响应。根据估计利润、现金安全垫、储量和偏好挑选行动。

公开新闻说明结果，如“赤曜新矿投产，预计未来铁钛矿供给增加”，而不是突然对玩家施加无来源的价格惩罚。

AI 不读取未公开的玩家扫描结果、不操纵玩家井道、不偷改玩家库存。难度差异通过初始资本、风险偏好和决策精度配置。

### 13.4 AI 与终局

商业竞争应让机会变化，但不能让单个对手永久锁死唯一通关路径。关键矿物至少有替代来源；错过一个合同还会有其他合适合同。

星港股权、收购与复杂金融行为不进入核心开发依赖。若后续加入，只服务于具体运费优惠、分红或港口能力，不做完整证券交易系统。

## 14. 可选精炼与星港投资

### 14.1 单步骤精炼

在采矿、运输和市场已经成立后，再加入两种加工品。四种主要矿物之外多出两个商品条目，必须承认库存与市场界面会增加复杂度。

| 配方示例 | 单位处理费 | 参考卖价 | 经营意义 |
|---|---:|---:|---|
| 2 t 铁钛矿 → 1 t 合金锭 | 20 Cr/产出吨 | 260 Cr/t | 提高货物价值密度 |
| 3 t 晶硅矿 → 1 t 高纯晶片 | 60 Cr/产出吨 | 650 Cr/t | 为高价值订单供货 |

每个配方还需要加工设备、处理时间、维护费与输出仓容。产出减少的质量记为工艺损耗，不另建废料系统。

加工品有独立且有限的需求。直接卖原矿、占用加工能力与等待高价订单之间应当都有成立的情境。

单个精炼站同时选择一个配方，不支持多层链式配方。加工开始时锁定输入和输出仓容，完成时统一转化，避免存档或取消导致材料复制。

### 14.2 星港投资

先采用“参与具体扩建项目”的方式：

- 投入现金或交付材料。
- 项目完成后增加仓储、装卸泊位，或获得期限明确的费用优惠。
- 费用优惠不能叠加成负运费。
- 可以不参与，继续使用原有服务或其他港口。

股权交易和分红作为后续内容，不能成为首发基础物流成立的必要条件。

## 15. 成长节奏、教学与长期内容

### 15.1 前一小时

下面的时间是试玩观察目标，不能通过强制等待机械地凑到该分钟。

| 时间 | 玩家行动与发现 | 系统引入 |
|---|---|---|
| 0–5 分钟 | 扫描、建第一条井道、看见矿石产出并完成首笔销售 | 当前矿场、现金、轻型船 |
| 5–15 分钟 | 找到第二片矿，比较延伸井道、平台扩容和运输投入 | 一次真实预算取舍 |
| 15–30 分钟 | 发现晶硅矿或一个短合同机会 | 第二种矿物、库存预留 |
| 30–60 分钟 | 勘探邻近星球，建立第二经营点或完成开发准备 | 星图、跨矿场资金和运力分配 |

不要求玩家在一小时内完成所有系统；重点是看到扩张机会，并理解自己下一步需要什么。

### 15.2 教学方式

- 每次只提示当前目标所需的一两个动作。
- 提示锚定实际矿体、按钮或船只，不播放大段规则说明。
- 玩家已经完成相应动作时，教学自动跳过。
- 第一次错误规划可以撤销未开工订单；已开工项目按明确规则结算。
- 首次装满仓库触发瓶颈解释，不额外罚款。
- 首次扩张展示“新项目会占用哪些现有资源”，不代替玩家自动投资。
- 提供“我熟悉经营游戏”的简化教学选项，但初始世界规则一致。

### 15.3 长期成长

| 阶段 | 经营变化 | 新挑战 | 减少重复劳动的方法 |
|---|---|---|---|
| 起步 | 一座矿区、一条航线 | 找矿与第一次回款 | 默认自动发货 |
| 建立公司 | 两三个经营点 | 钱和船不能同时满足全部机会 | 集团对照、固定航线 |
| 跨系扩张 | 多矿种、多港口 | 距离、合同、矿区接替 | 共享船池、集中预留 |
| 区域经营 | 多个稳定基地 | 深井、干线运力、AI 投产 | 中转、汇总告警 |
| 集团终局 | 有能力完成大型项目 | 多地点持续交付、资本集中投入 | 批量策略与经营总览 |

新阶段优先通过已有能力和经营成果解锁，不单纯要求挂机达到某一天。

### 15.4 必须有区别的经营情境

至少做出以下六类可玩的机会，再考虑铺大量同质星球：

1. 近港低值矿：利润取决于规模与低成本运输。
2. 深层大矿：投入高、回本慢，但可长期稳定供货。
3. 远港稀有矿：高单价却占船时间长，需要比较船日贡献。
4. 多片浅矿：适合轻资产试采，便于设备反复搬迁。
5. 受限地表富矿：需要优化共用主井与提升能力。
6. 阶段性需求矿：订单窗口明确，考验建设与交付安排。

区别来自规则组合，不仅是换矿物颜色。

### 15.5 特殊发现与事件

| 事件 | 已知信息 | 可选行动 | 代价与结果 |
|---|---|---|---|
| 超大型深矿 | 储量区间、硬岩结构 | 详勘、分期开采、放弃 | 信息费与前期投资 |
| 造船需求扩张 | 生效日期、持续区间、需求矿种 | 备货、接合同、维持现状 | 资金占用与错失其他机会 |
| 航道检修 | 提前公布检修期 | 提前发货、绕行、暂缓 | 仓储与绕行费 |
| 古代探测阵列 | 一次调查费用、可能的信息收益 | 调查或出售发现权 | 提供新情报或特定科研机会 |
| 新港建设 | 位置、投产预期 | 提前布局或参与扩建 | 资金被长期占用 |
| 竞争者增产 | 可观察的矿区和运输变化 | 转矿种、争订单、压低成本 | 同行竞争改变价格预期 |

大部分负面商业事件提供预告。无法预告的事件限制影响范围，并提供可理解的应对。

全局重大事件不同时堆叠过多：初值最多 2 个；新手保护期内不触发破坏基本循环的随机事件。每类事件设冷却期，避免新闻滚动却没有新决定。

### 15.6 终局目标

玩家可选择一种目标，也可在同一存档继续完成其他目标。以下为目标结构，具体吨数与资产门槛在中期经济稳定后标定。

| 路线 | 完成条件结构 | 最后阶段的玩法 |
|---|---|---|
| 商业霸主 | 在可用星团中建立稳定业务；连续两个财报周期保持正经营结余；在集团资产排行领先并完成一次旗舰供应项目 | 同时守住现金流与扩张效率 |
| 深空先驱 | 完成指定独特天体调查、获得四类矿物样本、建成深空观测工程 | 多区域勘探与远距离样本交付 |
| 星际工业巨头 | 建立至少一处中转枢纽；连续完成多港口交付项目；最终持续供应大型建设工程 | 航网、仓容、运力与交付调度 |

终局不单纯看现金达到某个数字。工程分为可理解的几个阶段，不重复要求几十次同样的订单。

完成目标后保留世界，玩家可继续经营或创建新种子。重复游玩来自星图、矿体、港口需求、竞争者行为与发现顺序变化。

## 16. 画面、界面、声音与可读性

### 16.1 美术方向

采用清楚的科幻工业造型：矿机轮廓可辨、矿物与岩层区分明确、火箭有体积感和起飞反馈。背景可以精致，交互对象保持清晰。

界面使用克制的深色或中性面板、少量蓝色状态色与暖色操作强调。红色只用于实质风险，不把所有按钮都做成发光高对比。

已有概念图可以作为氛围参考，但图上的“真实轨道参数、燃料、多套资源、母港股份”等标签不自动进入玩法需求。

### 16.2 矿场布局

- 中央约 65–70% 可用面积用于矿场。
- 顶栏：公司现金、冻结金额入口、游戏时间、速度。
- 左侧：扫描、钻井、采掘头、仓储等当前工具。
- 右侧：选中对象详情；未选中时显示当前主要瓶颈与下一班运输。
- 底部：实际产量、矿仓占用、预计运输能力与矿体寿命。
- 星图、集团、研究、合同通过统一导航切换，不全部常驻展开。

### 16.3 每个主要操作都要有预览

| 操作 | 确认前必须显示 |
|---|---|
| 钻探 | 费用、工期、未知风险、可连接矿体 |
| 扩容 | 新上限、仍存在的其他瓶颈 |
| 买船 | 到货时间、适用航线、预计新增运力 |
| 改派船 | 新航线收益预估、原航线产能缺口 |
| 接合同 | 冻结保证金、交付缺口、期限 |
| 封存 | 停产影响、费用变化、未完成运输 |
| 搬迁 | 时间、运费、库存和合同影响 |

### 16.4 瓶颈解释

示例文案：

- “当前运输不足：日产约 300 t，日均可运约 200 t。按当前生产速度，约 5 日后满仓。”
- “主井限制产量：两个采掘头合计可产 80 t/日，主井只能通过 60 t/日。”
- “船只等货：当前可装 42/100 t，最多再等 0.8 日。”
- “合同风险：按当前航次预计少交 80 t；增加一趟轻型船运输可能补足。”

预测必须标明前提，信息不足时显示范围或“缺少数据”，不能给伪精确数值。

### 16.5 通知分级

| 级别 | 示例 | 行为 |
|---|---|---|
| 信息 | 研究完成、发现普通新矿 | 汇总显示 |
| 关注 | 预计储量不足 15 日、满仓趋势 | 列入集团待办 |
| 紧急 | 合同即将违约、现金不足、重要航线阻塞 | 高亮并可选自动暂停 |

相同对象、相同原因合并通知，只在状态变化或明显升级时再次提示。不因每个模拟步仍然满仓就重复报警。

### 16.6 操作与可访问性

- 默认空格暂停、数字键控制速度、Esc 退出当前工具。
- 键位可改；鼠标拖动平移、滚轮缩放。
- 矿种同时使用颜色、图标和名称，不只靠颜色区分。
- 支持界面缩放，关键文字不依赖贴图。
- 发射动画可跳过或缩短；不会阻塞其他矿区经营。
- 重要操作有清晰撤销边界，避免误拆已投入设施。
- 保存鼠标位置以外的视角状态，但视角不是世界状态。

### 16.7 声音反馈

重点制作扫描确认、钻入矿体、持续采掘、装载完成、火箭发射和交易到账。多矿场后台声音不同时叠加，当前矿场外的活动用轻量提示表现。

环境音乐和星球氛围可以随区域变化，不以大量对话配音增加制作量。

### 16.8 2D / 2.5D 的具体实现方式

本项目的“2.5D”主要指二维操作中的体积感、层次和光影表现，不要求把整个矿区改成三维世界。优先统一观看角度、光照方向、建筑比例和材质风格，再逐步提升精度。

| 内容 | 首选实现 | 后续可选增强 |
|---|---|---|
| 星球整体外观 | 预渲染球体素材与简洁旋转表现 | 在独立预览中使用 3D 球体 |
| 地表与地下剖面 | 二维地形、岩层贴图、多层远景 | 更细致的材质与局部动态效果 |
| 矿脉 | 二维矿体轮廓、纹理、受控发光着色 | 扫描波纹与开采状态变化 |
| 钻机、采掘头和输送 | Sprite2D 类表现与独立动画场景 | 更多工作阶段与升级外观 |
| 火箭发射 | 二维起降动画、尾焰、音效 | 少数重大节点使用可跳过的 3D 演出 |
| 星际地图 | 二维节点、航线与飞船标记 | 背景视差、轻量轨道装饰 |
| 科幻界面 | Control、容器、共用 Theme | 统一边框、状态过渡和悬停反馈 |

以上是本项目的美术方案。矿脉发光、运矿颗粒和火箭尾焰不参与实际产量、库存与航次计费。

制作顺序：沿用当前可玩画面 → 统一图标、布局与交互反馈 → 替换主要设施与地形素材 → 增加少量发射和发现演出。每一步都应能继续试玩，避免美术升级切断现有闭环。

已有 AI 图片用于提取造型、色彩和构图方向。制作游戏素材时拆成可复用的背景、设施、矿体和特效；交互文字与数值由界面实时绘制，不固定在整张概念图中。

### 17.2 首个完整试玩的资产预算

建议先复用已有资产，缺少时再补：

- 3 套星球地表/天空组合，可共享基础岩层。

- 1 套平台、采掘头、矿仓、起降设施及升级变化。

不要先生成几十张完整矿场背景，再强迫玩法适应图片中的建筑位置。

### 17.3 内容配置的最低字段

每项内容至少具有稳定 ID、显示名称、解锁条件、数值参数、视觉引用、说明与版本。名字可以变，存档引用的 ID 不随文案翻译改变。

## 18. Godot 实现方向与状态架构

本项目确定以 Godot 为后续设计与开发的默认引擎。二维矿场、程序化世界、经营界面和后台经济模拟与本方案的实现方向相符；具体性能取决于数据规模与实现方式，通过第 18.8 节验证。

**推荐技术基线**

| 项目 | 本项目选择 | 已有工程处理 |
|---|---|---|
| 引擎 | Godot 4.x 稳定版；本次核验的新项目基线为 4.7.2 Stable | 记录并优先沿用现有稳定版本，升级单独验证 |
| 语言 | GDScript，关键状态和接口使用类型标注 | 已有 C# 模块先保留，不因本文重写 |
| 主玩法 | 2D 逻辑 + 2.5D 美术表现 | 复用现有场景与资产 |
| 星图与矿区 | 程序生成数据 + TileMapLayer 或现有二维绘制方式 | 不强制替换可用的多边形或网格实现 |
| 界面 | Control + 容器 + 共用 Theme | 先统一样式和职责，再逐步整理布局 |
| 静态配置 | Resource / JSON，选择清楚的唯一权威来源 | 禁止两份同名配置各自维护不同数值 |
| 经济模拟 | 固定游戏时间步、前后台共用规则 | 从当前循环逐步提取模拟逻辑 |
| 存档 | 版本化状态，写入 user:// | 保留现有 ID 与迁移路径 |
| 首发目标 | Windows 桌面版，Steam 作为目标发行渠道 | 先形成可独立运行的构建 |
| 网页试玩 | 可选独立验证项 | 不默认要求与桌面完整版本同步交付 |

截至 2026-11-07，官方归档列出 Godot 4.7.2 为稳定版本，4.8 处于 Beta 阶段。[技术参考 R4] 该版本信息是本次核验结果，不代表已有项目已经安装此版本，也不构成自动升级指令。后续选版仍以项目依赖和当时官方信息为准。

默认使用 GDScript 是本项目的开发选择。GDScript 支持变量、参数和返回值的类型标注，可在关键经济接口上增强检查与可读性。[技术参考 R9] 不必仅为了类型检查而切换语言；若实际工程已经使用 C#，先评估导出目标和现有成果再决定。

本章的文件名称用于说明职责，不要求把现有目录改成同样结构。

### 18.1 分离定义、运行状态、模拟和画面

| 层 | 内容 | 约束 |
|---|---|---|
| 静态定义 | 矿物、设备、船型、科技、事件模板 | 可用 Resource 或现有配置方式；运行中不直接改模板 |
| 运行状态 | 现金、矿量、库存、设施、船舶、合同、世界时间 | 由唯一权威状态维护 |
| 模拟规则 | 采矿、物流、市场、建设、AI、研究 | 按统一时钟推进，能脱离画面运行 |
| 展示交互 | 星图、矿区、面板、动画、声音 | 发出操作请求，读取已提交结果 |

Godot 官方将 Resource 定义为数据容器，并说明已加载资源可能被复用。[技术参考 R1] 因此船型定义可以共享，而“这艘船的载货量”应保存在该船独立运行状态中，避免修改一艘船污染全部同类船。

### 18.2 推荐模块职责

| 逻辑职责 | 输入 | 输出/状态变化 |
|---|---|---|
| 世界与勘探 | 种子、调查操作 | 天体、矿区、情报状态 |
| 建设 | 施工指令、预算 | 工单、已建网络与设施 |
| 采矿 | 矿体、设施、dt | 开采量、矿量消耗、变动费用 |
| 库存 | 转移、预留、消费请求 | 位置化库存和预留记录 |
| 物流 | 航线、船、货物任务 | 航次、装卸、到达事件 |
| 市场 | 到港供给、买方需求 | 报价、额度、销售 |
| 合同与工程 | 交付、时钟 | 完成度、收入、保证金与违约 |
| 经济 | 经核验的交易 | 现金、冻结资金、费用、债务 |
| 研究 | 预算、样本、dt | 研究进度和解锁 |
| AI | 可见信息和自身资产 | 合法经营指令 |
| 存档 | 完整状态 | 版本化保存/加载 |

系统共享稳定 ID，不直接把 UI 节点当作业务对象传递。

### 18.3 Godot 场景使用

矿场视图以 Node2D 组织地表、岩层、矿体、设施与运输表现，使用 Camera2D 浏览矿区。界面以 Control 和容器组织；需要固定在屏幕上的 HUD 可放在 CanvasLayer 下，避免随矿区镜头一起移动。[技术参考 R10]

新做的图块地图优先使用多个 TileMapLayer 分别表达岩层、矿体显示、建造提示和迷雾等内容；不要求全部层都采用图块。官方说明 TileMapLayer 是单层二维图块节点，可用多个节点组合不同层，旧 TileMap 已被弃用。[技术参考 R5]

TileMapLayer 是地图显示方式，不能成为矿物储量、采掘范围和库存的唯一存储位置。逻辑网格由 MineState 等状态维护，画面按状态刷新；更换贴图或卸载画面不会改变地下剩余矿量。

钻机、采掘头、仓库和火箭使用可复用的独立场景。井道可沿用现有绘制方式或使用线段/网格表现，不为每一吨矿石创建节点。已有多边形矿体、旧版图块或批量绘制已运行良好时，先建立数据适配，迁移作为独立任务。

共用 Theme 管理字体、间距、面板、按钮与选中状态；主题文件单独维护，以便矿场、星图和市场保持一致。Godot 的 Theme 编辑器支持集中编辑样式并预览控件状态。[技术参考 R6]

可以设置一个跨场景存活的 GameSession 持有当前存档和时钟，但不把所有模块都做成随处可改的全局单例。官方说明 Autoload 可跨场景保留，也提示应控制全局状态的耦合。[技术参考 R2]

切换矿场时，只切换该矿场的可视实例；后台矿场继续参与同一套模拟。

### 18.4 操作命令

建议所有经济操作经过一致入口，名称仅为示意：

    ScanArea
    BuildDrill
    PlanBore
    PlaceMiningHead
    UpgradeFacility
    PurchaseShip
    AssignRoute
    SetSalePolicy
    ReserveInventory
    AcceptContract
    StartResearch
    MothballMine

每条命令包含唯一 command_id、对象 ID、预期条件与参数。处理时：

1. 校验对象和状态。
2. 校验现金、库存、权限和前置。
3. 一次性提交相关变化。
4. 记录结果，重复提交同一 command_id 不重复扣款。
5. 返回可读的成功或失败原因。

不要求引入完整事件溯源框架；简单的命令校验与事务式修改已经能避免大量重复扣款和幽灵库存。

### 18.5 统一时间步

时间口径沿用第 2.2 节：1 tick = 1/60 游戏日；1× 时约每 0.5 秒现实时间推进一次。本文统一使用“游戏日”和“tick”，不另引入一套按游戏分钟计算的产量参数。时钟以现实经过时间累计应推进的 tick 数，再按倍率执行；动画插值与界面刷新独立处理。

建议每步按固定顺序处理：

1. 在 t0 接收有效命令，锁定本步所需现金、货物和容量。
2. 使用 t0 已存在的设施和任务计算 t0 → t1 的进度；本步刚完工设施不追溯生产。
3. 按固定对象顺序结算施工完成、运输到达/装卸、采矿入库与费用。不能使用尚未提交的预测产量。
4. 到达日界线时更新当日报价与采购额度，然后执行合法销售、交付和研究结算。
5. 先处理截止时刻及之前的有效交付，再判定到期违约。
6. AI 根据已提交状态规划下一步命令，更新通知并生成存档快照点。

所有业务截止时间量化到模拟 tick；恰好在截止 tick 完成卸货的货物算按时到达。不可依赖帧回调顺序决定合同成败。

### 18.6 数值与随机

- 内部质量使用整数 kg，界面显示 t；货币使用最小货币单位整数。
- 速率产生的不足一个整数单位的余量继续累积并存档，避免小产量长期被截断。
- 路线进度和研究进度可用固定 tick 或带明确精度的数值。
- 世界生成、市场、AI、事件使用独立随机流并保存状态。
- 打开地图、播放动画、切换界面不消耗经营随机流。
- 稳定排序对象 ID，避免遍历容器顺序改变经济结果。

### 18.8 性能原则

- 后台矿场使用轻量数据，不实例化全部动画和矿石粒子。
- 同一套公式用于前台和后台，不能“后台直接发钱、前台才算库存”。
- 优先做每 tick 的聚合计算，不为每吨矿创建节点。
- AI 低频决策，市场按日更新，通知按变化合并。
- 性能问题先测量再决定是否使用线程或原生扩展。
- 目标可暂定 1080p 下流畅交互与稳定 4× 模拟；具体 FPS、内存和存档大小必须在确定参考机器后验收，本文不作性能保证。

扩容验证分别使用 3、8、20 个活跃矿区，并记录后台模拟耗时、界面响应和存档体积。星图中可发现 100 颗天体，不等于必须同时实例化 100 座完整矿场。状态与画面分离能减少扩展时的耦合，但不能保证增加到任意规模都无需优化。

### 18.10 渲染方式与平台安排

新建的二维经营原型可优先验证 Compatibility 渲染方式；这是便于桌面与可选网页试玩共享基础表现的项目建议，不是所有 Godot 项目的强制选择。已有工程采用其他渲染方式时，先测量和检查特效依赖，不盲目切换。

| 目标 | 实施策略 | 验证重点 |
|---|---|---|
| Windows 桌面 | 第一发布目标，优先完成导出后的真实运行 | 字体、输入、路径、存档、全屏和性能 |
| Steam 发行 | 在桌面构建稳定后另列发行任务 | 发行包与后续平台功能 |
| 网页试玩 | 仅在有实际需求时提供较小体验版本 | 加载、浏览器存储、音频与性能 |
| 局部 3D 演出 | 独立视图或演出场景，可跳过 | 不阻塞模拟，不依赖演出结束来结算货物 |

官方 Web 导出文档当前说明：Godot 4 的 C# 项目尚不能导出 Web；Web 目标使用 Compatibility / WebGL 2.0，Forward+ 与 Mobile 渲染方式不支持该目标。[技术参考 R8] 因此采用 GDScript 有利于保留网页试玩选项，但仍需检查素材、扩展与浏览器限制，不能承诺桌面项目无需调整即可上网页。

若以后增加独立网页版本，要把桌面文件保存和浏览器持久化分别验收；浏览器关闭再打开后必须能恢复，不能仅测试同一标签页内读档。

### 18.11 首个 Godot 构建的交付检查

这些是后续开发任务，不是当前已实现功能：

1. 记录引擎完整版本、渲染方式、脚本语言和依赖，使用与该引擎版本匹配的导出模板。
2. 从现有主场景启动，完成一次扫描、钻探、产矿、装船、到港与销售。

4. 保存后关闭整个游戏进程，重新启动并加载，确认货物、现金和航次没有重置。
5. 导出 Windows 构建，在编辑器之外运行同一闭环。
6. 替换一项设施贴图或界面主题时，确认产能、库存与费用计算不受影响。
7. 单矿闭环已通过的项目直接进入 M2，不重新做同样的场景；第二矿区优先验证经营取舍。

## 19. 存档、兼容与恢复

### 19.1 保存什么

保存全部影响未来结果的状态，包括：

- 世界时间、随机流、生成版本和内容版本。
- 已生成矿区的真实矿体与剩余量，包括尚未扫描到的部分。
- 已揭示区域和玩家情报。
- 设施、井道、施工任务与已付款。
- 每个地点的库存、预留以及船舱货物。
- 船只位置、阶段、剩余时间、在途费用和路径。
- 合同保证金、交付记录、到期时间与状态。
- 贷款、应付款、科研样本、研究进度、事件持续时间。
- AI 的实际资产、已知信息和在途货物。
- 设置、视角和通知已读状态作为附属数据。

仅保存随机种子再重新生成整个已开发世界不够；生成器或内容升级后可能改变矿脉和航路。

### 19.2 文件写入

Godot 官方提供 FileAccess 与 JSON 等保存示例，并说明序列化需要显式处理不支持的类型。[技术参考 R3] 项目具体格式应结合现状选择，不把运行时 Node 引用直接写入存档。

项目内配置与素材通过 res:// 访问；玩家存档、设置和本地经营日志写入 user://。Godot 官方说明，导出项目的资源目录可能只读，而 user:// 用于持久化用户数据。[技术参考 R7] 建议按 saves/、settings/、logs/ 分开组织。既有存档若使用其他位置，迁移时提供兼容读取，不因为改目录就让玩家看不到旧档。

推荐流程：

1. 在模拟步结束时取得一致快照。
2. 写入临时文件。
3. 检查结构与校验信息。
4. 轮换保留上一份有效存档，再替换当前文件。
5. 只有写入成功才显示“保存完成”。

对替换过程进行中断恢复验证。若最后一次写入无效，明确提供上一份有效存档，不能静默创建一个新世界覆盖原存档。

### 19.3 版本迁移

存档使用独立 schema_version，迁移一次只跨一个版本。迁移函数应可重复验证，并在副本上执行。

- 旧 ID 通过映射保留。
- 缺少新字段时采用明确默认值。
- 船型容量降低时不丢弃已经在船上的货物；保留该航次旧容量快照，下一次装货再使用新规则。
- 仓容下调时已有库存进入不可新增的溢出状态，必须运出后恢复正常，不能直接删货。
- 已支付工单不因读档再次扣款。
- 旧技术与新技术映射不重复发放奖励。

### 19.4 采矿规则变化的兼容选择

如果旧版已经实现“接触矿脉就整片开采”，不能贸然把当前存档所有矿体改成局部采掘而不告知玩家。

优先顺序：

1. 新存档使用新规则，旧存档冻结旧规则版本；或
2. 为已开发矿体生成兼容采掘范围，保证迁移后当前可用产能不突然消失；新矿区使用新规则。

在明确当前存档重要性后选择一种，不同时长期维护多套任意规则。

### 19.5 存档验收

- 在采掘、装载、飞行、卸载、研究、拍卖和合同到期附近分别保存加载。
- 保存前后现金、质量总量、预留、剩余时间一致。
- 同一快照运行相同 tick 数后，核心经济结果可复现。
- 1× 与 4× 推进相同游戏时间，结果一致。
- 切换场景不重新计费、不重新生成矿体、不重置冷却。
- 旧版本样例存档迁移后，可以完成至少一个完整采矿—运输—销售循环。

### 20.5 修改优先级

- **P0：会破坏结果或存档。** 重复扣款、凭空产矿、货物消失、读档重置、场景切换停产、合同重复结算。
- **P1：核心决策无法成立。** 采矿形状无差别、船只没有真实载重、矿仓满了仍无限挖、第二矿区仅换背景。
- **P2：体验负担。** 重复发射、通知轰炸、需要逐个矿场查状态、缺少费用解释。
- **P3：内容与表现。** 更多星球、皮肤、动画、额外事件与音效。

已完成 P0 的模块无需为文档统一而再次重写。单轮优先选择一个 P0 或一个闭环 P1。

### 20.6 每次变更记录

记录：问题触发条件、原行为、目标行为、受影响文件、是否影响存档、验证方式、已知限制。

例如：

> 两艘船同时装一座矿仓时，旧实现可能重复取货。本轮仅为装载增加批次预留与原子转移，复用现有飞船动画。验证两艘船、尾矿与保存加载三个情境。

## 21. 分阶段开发任务与完成标准

不提供未经代码审计的固定工期。工作量可以在审计后分为小、中、大，但不能把“预计几天”当成用户当前项目的事实。

### M0：确认现状与保留基线

**任务：** 找到项目入口、启动方法、主要状态、现有存档、配置和已有检查；运行当前版本或明确运行受阻原因。

**产出：** 功能盘点、可运行基线、规则差异清单、下一项最小任务。

**通过条件：** 每个“已完成”都有代码、运行或数据证据；原版本可恢复；没有把概念图当功能完成证明。

### M1：单矿场闭环可信

**任务：** 扫描、钻探、采掘范围、有限储量、矿仓、真实船舱、自动往返、到港销售、成本与保存加载。

**通过条件：**

- 一批矿能从矿体追踪到销售。
- 仓满和运力不足有正确行为。
- 不点击发射也能持续经营。
- 保存加载不重置矿量、船只或现金。
- 玩家能看懂当前瓶颈。

如果已有单矿场闭环，只修复缺口，不重做画面。

### M2：两颗星球产生取舍

**任务：** 两个不同地质矿区、两种矿物、至少两种投资用途、真实航程、有限资金与船只。

**通过条件：**

- 第二矿区需要不同开发方案。
- 同一笔现金在不同情境下有不同的合理用途。
- 船只改派会改变两座矿区的结果。
- 后台矿区不因离开画面而停产或简化成自动送钱。
- 扩张后操作量可控。

这是最重要的玩法检查点；没有通过之前，不扩大到完整星域。

### M3：完整试玩可交付

**任务：** 三颗星球、两个港口、两矿种、两船型、少量研究、合同、一个 AI、集中管理、首次扩张教学。

**通过条件：**

- 能独立试玩约 1–3 小时并形成后续计划。
- 合同能部分交付、完成、取消、违约。
- AI 受预算与货源约束。
- 用户可以保存退出，重新启动后继续。
- 达到目标不是只能等待同一条赚钱路线。

试玩时长是验证目标，不是强制用研究计时器延长。

### M4：长期经营基础

**任务：** 跨星系、多矿区接替、设备搬迁、三船型、四矿种、共享船池、中转与区域特色。

**通过条件：**

- 5–8 个活跃经营点不需要逐一点击日常运输。
- 旧基地和轻型船仍有用途。
- 多次枯竭不会造成强制重复建同一套设施。
- 至少三种不同投资组合能完成主要经营目标。
- 长时间运行后库存、贷款和市场不发生无约束膨胀或不可恢复死锁。

### M5：战役与发布准备

**任务：** 特殊天体、终局项目、长线平衡、完整存档迁移、性能、音效、美术一致性、导出构建与新玩家测试。

**通过条件：**

- 从新档到至少一个终局目标有完整路径。
- 目标资源没有循环依赖或唯一来源被永久封锁。
- 可在结束目标后继续经营。
- 崩溃/中断后有有效存档恢复路径。
- 30–50 小时目标有实际试玩记录支撑；若尚未验证，对外不作已实现承诺。

## 23. 验证、试玩与平衡

### 23.1 必须满足的数据不变量

- 现金、自由库存、船舱载重不出现未经定义的负数。
- 货物只在一个实际地点存在。
- 同一库存单位最多被一个排他交付任务预留。
- 对固定世界中的资源：地下剩余 + 各处库存 + 已出售/消耗/工艺损耗，能对上初始总量及明确外部来源。
- 船只不能同时执行两项航次。
- 合同、研究和建设奖励只结算一次。
- 资金冻结不同时算作支出和可支配现金。
- 加速、暂停、切场景不改变同一游戏时间内的经济结果。
- AI 新增产量和市场成交都有可追踪的货源。
- 新生成矿区或外部采购加入质量统计时具有明确来源记录。

### 23.2 关键情境

| 情境 | 预期结果 |
|---|---|
| 两个采掘头覆盖仅剩 10 t 的矿体 | 合计最多产出 10 t |
| 两个采掘头共用 60 t/日主井 | 实际合计不超过 60 t/日 |
| 矿仓满载 | 生产暂停或减速，矿体不无故减少 |
| 剩余尾矿 37 t、船容量 100 t | 等待上限或收尾触发后运输 37 t |
| 两艘船同时申请同一批货 | 一次性预留，不超额装货 |
| 港仓只剩 20 t、船有 100 t | 最多卸 20 t；余货留船，后续按规则继续 |
| 货物为合同预留但现货出现高价 | 不被默认现货策略出售 |
| 截止 tick 完成有效卸货 | 算按时交付，之后再检查到期 |
| 合同完成后读档重入场景 | 不重复发货款或释放保证金 |
| 现金不足启动新航次 | 不起飞；已预付航次仍可结束 |
| 更换航线时船仍在途中 | 在允许的节点改派，不瞬移 |
| 切走矿场运行 30 日 | 与停留该矿场的核心结果一致 |
| 保存发生在装载中 | 预留与实际船舱仍保持一致 |
| 贷款后申请更多贷款 | 不把借来的现金当新增抵押资产 |
| 卖出设备后重复提交命令 | 不重复获得回收款 |
| 调小新版仓容后加载旧档 | 进入溢出待清理，不丢货 |
| 普通买方额度耗尽 | 不继续成交负额度 |
| AI 参与竞拍 | 出价受其可用现金约束 |

这些是设计验收要求；在取得实际代码前，不应声称它们已经通过。

### 23.3 玩法试玩

先找 3–5 位未参与设计的人进行探索性试玩，样本用于发现问题，不用于证明市场成功率。

观察并记录：

- 第一次有效采矿与第一次销售发生在何时。
- 玩家能否解释最近一次停产或亏钱的原因。
- 第一次扩张是自主形成计划，还是完全跟随提示。
- 玩家是否考虑过两个不同投资方案。
- 第二座矿场是否需要不同建设方法。
- 同时经营三座矿场时，是否反复做无策略价值的点击。
- 玩家是否知道下一步想买什么、为什么要买。
- 离开时是否有明确未完成计划；愿意继续的表态不能替代实际继续游玩的观察。

### 23.4 本地调试记录

使用本地日志即可：建设、扫描、采购、开采量、装卸、销售、亏损、合同、暂停、切场景和保存失败。

记录游戏 tick、对象 ID、关键数量和原因。首阶段不需要联网遥测平台、账户系统或在线服务器。

### 23.5 判断问题对应的修改

| 观察 | 优先修改 |
|---|---|
| 玩家只选最近接触点，矿体形状无意义 | 检查采掘范围、共享主干和深浅矿成本 |
| 所有人只买最大船 | 检查装载率、购买成本、固定维护和货源规模 |
| 所有人永久囤货 | 检查仓储费、资金用途、需求与价格预期 |
| 所有人到港立即卖 | 检查是否存在真实交付窗口与可负担的持有机会 |
| 玩家总被合同坑 | 检查到港预测、期限提示和交付规则 |
| 扩张后变烦 | 提前自动化、集中管理、减少重复告警 |
| 几小时后只剩等钱 | 检查是否还有新的地质、航运与投资决定 |
| 矿区枯竭令人厌烦 | 延长基础设施价值、增加邻近开发和设备迁移便利 |
| 前期始终没有资金压力 | 调整外部补贴与扩张投入，检查重复收入漏洞 |
| 多种策略都无法生存 | 先核验单位、费用重复计算、运输空载与初始保障 |

不要求玩家一定囤货，也不要求一定用三种船。目标是在不同可解释的情境下存在不同合理选择。

## 24. 决策记录、风险与下一步

### 24.1 本版确定的规则基线

1. 陌生星域、持续集团经营、PC 单机。
2. 星图体现规模，矿场以二维地下剖面实现。
3. 固体矿通过有限采掘范围开采，地下共享输送有容量。
4. 采矿、库存、船舱、港口和交付具有统一的资源流。
5. 基础生产、运输与销售规则从早期自动执行。
6. 资源枯竭推动接替，但已有基地和设备可继续利用。
7. 现货按成交价，合同按锁定价；交付发生在指定地点。
8. AI 可抽象模拟，但遵守资金、储量与运输约束。
9. 普通设备现金采购，研究与工程消耗实际交付矿物。
10. 保存全部影响未来结果的状态，兼容已产生的用户存档。
11. 先用小规模世界证明策略，再增加星团与特殊内容。
12. 以现有项目为基础逐步改造。

### 24.2 待实际项目确认

| 项目 | 当前处理 |
|---|---|
| 引擎版本与语言 | 新模块默认 Godot + 类型标注 GDScript；实际版本/既有语言待核验，优先沿用 |
| 已实现模块与代码质量 | 待项目审计，不能由设计稿推断 |
| 当前存档是否需要保留 | 默认保留；迁移前使用副本 |
| 矿区当前是格子、多边形还是预制地图 | 复用现有表现，统一底层规则 |
| 当前是否已有真实运输和多地点库存 | 作为最优先核验项 |
| 首发内容范围与时长 | 在 M3、M4 试玩后确认 |
| 数值是否平衡 | 本文仅完成规则与示例计算检查，未做游戏平衡实测 |

### 24.3 三个主要设计风险

**风险一：前期采矿好玩，后期重复。**  
通过采掘结构差异、远距离经营、集团调度与大型交付改变决定类型；用实际后期存档试玩检验。

**风险二：系统很多，但玩家看不懂因果。**  
每个停产、缺钱、延迟都要能定位原因，并给出相关可执行入口；减少不提供决策信息的数字。

**风险三：已有项目被新方案拖入重写。**  
先盘点和映射，使用适配与分阶段替换。把“最终想有的功能”与“下一次必须改的代码”分开。

### 24.4 下一次实际开发的推荐起点

首先核验一批矿石能否经历下面全过程：

矿体减少 → 本地仓库增加 → 装船 → 船舱持有 → 目标港卸货 → 成交 → 现金增加。

随后核验：保存加载一次、切换场景一次、增加第二座矿场后，过程是否仍然成立。

若这条链已经完整可信，直接进入第二矿区的策略差异和集团操作负担；不重新制作同样的基础功能。
