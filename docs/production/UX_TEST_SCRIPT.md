# UX V1.0 用户测试脚本与验证矩阵

> 本文件规定**要做的测试**。在没有 Godot 二进制的制作环境里未执行实际 GUI/Headless 测试，不能将本文当作运行报告。

## 任务型测试（建议找 5 位未看过设计文档的参与者）

| 编号 | 对测试者只说什么 | 观察指标 | 通过目标 |
|---|---|---|---|
| T01 | “你是矿业公司的老板，请开始经营第一轮。” | 能否找到竞拍入口，是否被财务选项分心 | 4/5 独立成功 |
| T02 | “购买一处你认为合适的矿区。” | 点击路径、是否理解价格/资源未知 | 4/5 独立完成 |
| T03 | “找出这片星域可以采矿的地方。” | 是否发现探测器可以从基地拖动到天体 | 4/5 独立完成 |
| T04 | “让这颗矿星开始产出。” | 能否找到采矿部署并理解资金变化 | 4/5 独立完成 |
| T05 | “把矿运到港口。” | 是否了解“需要运力而不只是产量” | 4/5 独立完成 |
| T06 | “选择更合适的火箭，换一个零件。” | 是否理解部件拖放合法插槽 | 4/5 独立完成 |
| T07 | “把矿石卖掉。” | 买价识别、库存理解、按钮位置 | 4/5 独立完成 |
| T08 | “看看你赚了多少钱，然后进入下一轮。” | 是否看懂利润是收入减成本、下一轮 CTA | 4/5 独立完成 |

### 记录字段
- 测试设备、分辨率、Godot 版本、是否第一次进入。
- 每个任务：成功/失败、耗时、点击/拖动次数、是否需要提示、误解原因。
- 建议录像，标注首个犹豫点、误触点、违反预期操作位置。
- 每页的“第一眼主要操作”是否在 5 秒内被识别。
- 测试人员反馈分开记录：**事实观察**、**使用者意见**、**开发者解释**，避免混淆。

## 程序侧 Smoke Test

在装有 Godot 4.2+ 的环境中运行：

```bash
godot --headless --path . --editor --quit

godot --headless --path . --script res://scripts/tests/test_ux_flow.gd
```

手工分别 F6 运行：
- `res://scenes/demos/hq_demo.tscn`
- `res://scenes/demos/auction_demo.tscn`
- `res://scenes/demos/expedition_demo.tscn`
- `res://scenes/demos/assembly_demo.tscn`
- `res://scenes/demos/market_demo.tscn`
- `res://scenes/demos/settlement_demo.tscn`

手工必测边界：
1. 没有矿区权时扫描，不能扣费。
2. 已经竞拍一次后重复竞拍，不重复扣费。
3. 已扫描后重复拖探测器，不重复扣费。
4. 没有资源时不能运输；未交付时不能卖出。
5. 售出后重复点击，不能重复入账。
6. 发动机不能拖到货舱插槽；允许点击组件 + 点击同类槽位的替代操作。
7. 浏览器/窗口在 1280×720 和 1920×1080 下不遮挡 CTA。
8. 无 hover 或缩放情况下，主要按钮仍可被读取；颜色不可作为唯一状态信息。
