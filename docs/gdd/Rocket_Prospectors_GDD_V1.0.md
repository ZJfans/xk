# 0. 执行摘要与决策状态

## 0.1 一句话定义

**《星矿大亨》是一款短局经营、长期成长的太空采矿策略游戏。玩家竞拍陌生星域的开采权，发射探测器寻找矿体，部署采矿设备，利用一次性或可回收火箭运输矿石，在动态市场中择价出售，再把利润投入科技、下一轮资源竞争和星域公司股份。**

对标《石油大亨》的完整**经营结构**，而非复制“向下铺管道”的场景；《星矿大亨》的核心空间动作是**从基地向太空派遣探测器、采矿舱、火箭，并把资源运回来**。

## 0.2 已确定、暂定及未确定

| 状态 | 决策 | 解释 |
|---|---|---|
| **已确定** | 主类型是策略经营，不是飞行模拟、动作或火箭沙盒 | 操作服务经营判断；不做高保真轨道力学。 |
| **已确定** | 《石油大亨》本体的经营系统需有对应玩法 | 包括矿区/土地竞拍、股份、融资、酒馆交易、升级、市场、稀有资源、不同地区和短局结算。 |
| **已确定** | 星际采矿与火箭运输是核心差异 | 天体探索、设备投送、航线与载货能力都必须可视化。 |
| **已确定** | 一次性与可回收火箭均存在且有策略价值 | 前者低前置投资，后者高前置投资、低长期平均成本。 |
| **已确定** | 允许拖拽组装火箭，但组装不是每次运输的必经步骤 | 可使用预设型号、一键复用蓝图；避免独立变成《坎巴拉太空计划》。 |
| **已确定** | 第一款应能独立发布 | 不以“未来大作中的一个子系统”为发布前提。 |
| **建议默认，待验证** | 20 个战役经营回合、4 个星域、每回合 30 游戏日 | 目标总战役约 6–10 小时，最终以试玩调整。 |
| **建议默认，待验证** | 单回合 15–25 分钟 | 包含暂停、思考、买卖，时间加速可能缩短真实时长。 |
| **建议默认，待验证** | 2 家常规贸易商、3 家 AI 财团、4 种首发矿产 | 保持识别和数值调试可控。 |
| **建议默认，待验证** | 战役胜负主要由星域公司股份决定 | 每轮竞拍一批股权，战役终局以持股比例决胜，净资产作为同分判定。 |
| **延期但保留设计** | 熔岩、水冰、精炼、遗物收藏、深空挑战、多人竞拍 | 属于扩展路线，不得阻塞首个可玩切片。 |

**严格区分**：本文件出现的任何具体成本、容量、日期、AI 权重和价格均为**策划初值**，只有通过自动仿真和实际试玩才能成为最终平衡数据。

## 0.3 三个设计支柱

1. **看得见的经营**：扫描器会飞、设备会落地、采矿机会动、货船会装载和返航、资金入账有反馈；不允许所有动作只表现为数值变化。
2. **少操作、多取舍**：每次选择均围绕信息、成本、效率、市场或时机展开。玩家不需要重复点击采矿，不需要每次拼装火箭。
3. **短局决策与长期成长相互影响**：本轮赢得的现金，决定能否升级设备、争夺矿区和竞拍股份；长期投资反过来改变下一轮打法。

## 0.4 明确的非目标

- 不做真实 N 体轨道计算、复杂重力弹弓、飞船手动飞行和复杂气动/结构失效模拟。
- 不把多星球持续 30–50 小时集团模拟作为首发所必需的基础体验。
- 不在默认采矿主界面长期显示完整财务、科研、竞拍、酒馆、合同和火箭装配面板。
- 不要求玩家进入每颗星球后再玩一遍传统地下管道铺设；天体采矿在太空主场景内完成。既有地下剖面系统可在以后作为高阶矿区或独立挑战使用。
- 不复制《石油大亨》的美术、界面布局、文案、角色、地图和具体数值。

# 1. 玩家体验、核心循环及情绪曲线

## 1.1 玩家身份与幻想

玩家经营一家从小型发射基地起家的私人太空采矿公司。在陌生星域发现矿产、击败对手取得开采权，建立可以持续盈利的采矿与火箭运输业务，最终控制星域贸易集团。

玩家期待的是“这是我发现的矿，这是我部署的机器，这是我设计/挑选的火箭，这趟货帮我赚到了钱”，而不是面对一个繁复企业 ERP。

## 1.2 三层循环

**10–60 秒微循环**：发现矿点 → 下达操作 → 看到装置动作与数据变化 → 收到立即反馈。

**15–25 分钟单局循环**：勘探 → 建设采矿点 → 分配运力 → 观察两地报价 → 储存/出售 → 减少损耗 → 完成结算。

**战役宏循环**：总结收益 → 参加矿区及股份竞拍 → 购买升级/借贷/情报 → 选择下一轮策略 → 逐渐取得控股优势。

## 1.3 单局的三个节奏阶段

| 阶段 | 建议游戏日 | 主要问题 | 画面焦点 |
|---|---:|---|---|
| 开拓期 | D1–D8 | 信息不足，先勘探还是尽快投产？ | 探测器、未知天体、首次矿点部署 |
| 扩张期 | D9–D22 | 增加采矿效率还是解决运力和仓储瓶颈？ | 采矿设备、在途飞船、库存流动 |
| 冲刺期 | D23–D30 | 如何清理库存、完成回程并抓住最后高价窗口？ | 卖方报价、返航计时、结算预估 |

单局固定时长是为了迫使玩家做取舍，不应逼玩家手动收拾每一台机器。关卡结束时，所有未结算货物必须有明确规则，见第 8 章。

## 1.4 失败、学习与重玩动机

- 玩家允许输掉单轮（利润低、竞拍失败），但**不能因为一次失误就永久软锁整场战役**。
- 失败信息应具体指出：过高的采矿权价格、盲目勘探、火箭装载率过低、库存拥堵、过度囤货、利息压力等。
- 下一轮通过可见的设备升级和不同星域条件给出新的解法。
- 不使用玩家看不懂的随机价格暴跌或无预警火箭爆炸作为主要难度来源。

# 2. 产品范围、模式与游戏结构

## 2.1 游戏模式

| 模式 | 首发定位 | 游戏内容 |
|---|---|---|
| 战役（主模式） | **首发必备** | 完整总部—竞拍—开采—结算—升级—股权胜负流程。 |
| 单局挑战 | **首发必备** | 一张预设或生成星域，固定资源与规则，追求利润/效率评分。 |
| 自由经营 | 首发后优先 | 无强制 30 日结算，可持续运营，作为练习和放松模式。 |
| 特殊挑战/远征 | 扩展 | 资金限制、气候/重力限制、火箭限制、罕见资源任务。 |
| 多人拍卖与比分竞争 | 远期 | 独立经营、同步或异步竞拍，不以首发完成为条件。 |

## 2.2 战役骨架（建议初始版）

- 4 个星域，每个星域 5 个经营回合，共 **20 回合**。
- 每轮包括：总部准备 → 矿区采矿权竞拍 → 单局采矿与运输 → 结算 → 一场股权竞拍/总部投资。
- 进入下一星域时获得新环境限制、新矿种或交易技术，不一次暴露全部规则。
- 股份总发行量设为 100 个百分点；建议 20 次正式竞拍，每次 5 个百分点（可用固定或事件化方式调整，但总量守恒）。
- 战役最终按**星域公司总股权**排名；并列时比净资产，再并列比较现金。完整战役结束前玩家可以落后，但仍有翻盘空间。

上述轮次、发行规则、胜负阈值为原型默认方案，不是《石油大亨》的精确规则移植。若测试显示后期落后无法追赶，需重新设计发行节奏和 AI 出价能力。

## 2.3 章节解锁节奏

| 星域 | 新引入的主要机制 | 教学焦点 |
|---|---|---|
| I 晨曦边境 | 普通金属、基础探测、一次性运矿火箭、两家贸易商 | 学会探测—开采—运输—出售 |
| II 赤沙带 | 硬质矿体、设备损耗、可回收火箭、仓储升级 | 理解长期成本和产能瓶颈 |
| III 霜环群 | 星能晶能源订单、限时高价、发射窗口 | 物流时机与特殊资源应用；水冰补给留待扩展 |
| IV 幽光深空 | 高价值稀矿、深远航线、贸易增价、复杂竞拍 | 复合策略与资本配置 |

## 2.4 新手教程

采用“做一件事、得到一个结果、解锁下一件事”的操作式教程，不使用大段文字。

1. 镜头锁定一个亮起的未知矿体，提示点击扫描。
2. 探测器实际飞行，揭示可采储量范围。
3. 玩家把采矿舱拖到合法位置，看到半透明预览与价格。
4. 按确认后，设备运抵并进入施工/开采状态。
5. 玩家看到矿石进入矿舱，系统提示运输瓶颈。
6. 玩家把可用火箭拖到矿区或拖一条航线，飞船实际起飞。
7. 货船返航卸货；玩家比较两家报价，首次卖出。
8. 出现本轮净收益，提示仓储、运力或价格的下一步取舍。
9. 首局结束，返回总部体验升级和拍卖。第一局竞拍规则可以以简化模拟方式提前教学。

熟练玩家可以跳过新手教程，但不得跳过已购买资产和经济记录。

# 3. 世界、画面空间与直接操作

## 3.1 关键空间设定

**游戏一屏核心空间 = 下方/侧下方的发射基地 + 中上方可探索的太空资源带 + 贯穿其间的航线。** 这是一种 2.5D 游戏化空间表达，而非真实比例太阳系模型。

- 近处的资源可以是小型卫星、近地小行星。
- 更远处的资源可以是大型小行星、异星轨道矿区、特殊采矿站。
- 天体在屏幕上具备大小、岩层颜色、矿点、建设插槽与状态动画。
- 距离使用游戏化的“航程单位 L”或标准航时，由数据层决定；屏幕距离仅是可视化近似，不直接参与实际物理计算。
- 星域地图提供本轮可开发的若干矿体，**非完整银河百科**；完整区域选择留在总部竞拍层。

## 3.2 核心鼠标操作

| 意图 | 首选操作 | 系统反馈 | 是否改账本 |
|---|---|---|---|
| 查看天体 | 鼠标移入、单击 | 高亮、悬浮信息卡 | 否 |
| 侦察资源 | 选择探测器并单击/框选 | 扫描覆盖范围与费用预览 | 确认后才扣费 |
| 部署采矿 | 从工具条拖采矿舱至矿体 | 投放位置影子、资源预估、建造费用 | 确认后扣费 |
| 管理产能 | 单击已部署设备 | 小面板显示产能、效率、库存、瓶颈 | 升级确认后 |
| 指派火箭 | 拖动空闲火箭到矿体，或拖动建立航线 | 箭头、有效载重、预计航次利润 | 确认后 |
| 调整贸易港 | 点击航线/船只，切换目的地 | 路线颜色和收益预览更新 | 只改变调度，不直接卖货 |
| 出售库存 | 点击市场报价，拖动数量或按全部出售 | 显示已到账现金、剩余库存 | 原子成交后 |
| 查看总部 | 主导航切换 | 有明确场景过渡 | 否 |
| 火箭组装 | 独立装配车间内拖放部件 | 吸附/非法提示/实时性能 | 保存蓝图不扣费，生产才扣费 |

## 3.3 直接操作规则

- 单击只选中；拖动只产生**预览**；确认时才生成经济命令，避免误触扣钱。
- 已建造物体只能在明确的编辑模式里移动；移动可能产生费用，但必须有报价。
- 不可建造、未许可、航程不够、载重不足时必须给**具体原因和解决建议**。
- 主要操作均支持撤销尚未确认的预览；已成交交易遵循游戏规则，不允许无条件回滚。
- 默认鼠标为主要输入设备，键盘只提供快捷键。需要键盘缩放/镜头重置和无拖拽替代操作。

## 3.4 UI 层级与拥挤问题的硬性约束

默认采矿界面长期显示：**资金/日期/速度、小型任务提示、主场景、底部 4–6 个动词入口**。其余仅上下文显示。

- 主场景建议占有效宽度约 **70% 以上**（原型目标，按分辨率校验）。
- 左右功能面板不得同时永久占据大量空间；常驻侧栏优先只保留选中对象的详情。
- 每次打开面板必须给出明确关闭/返回途径；一个弹窗中不嵌套另一个复杂弹窗。
- 成功通知最多显示 1–2 个摘要；详细日志收在可展开的活动面板。
- 主流程操作不超过 2–3 层菜单；不应让玩家在集团、矿场和火箭屏幕之间频繁切换才能完成一次运输。

# 4. 总部、采矿权拍卖与竞争

## 4.1 总部定位

总部是两轮之间的**投资和竞争空间**，不是实时运转的复杂企业模拟器。

建议拥有可直接点击的建筑/分区：竞拍大厅、科研工坊、火箭工厂、银行、情报酒馆、经营记录、出发按钮。

## 4.2 矿区拍卖规则

**输入**：本轮可供拍卖的 4–5 处矿区卡片，展示星域、粗略资源评级、距离、环境风险、历史邻近矿区情报（若已解锁）。不直接公开精确矿脉数量、储量和矿石品质。**术语约定**：一份拍卖标的 `MiningLot` 是可开发的一个星域扇区，内含 3–5 颗可供勘探的天体；玩家赢得一份标的后，才能在该扇区内部选择具体矿点部署。拍卖一份标的不代表买下全星系。

**流程建议**：
1. 玩家与 3 个 AI 财团在候选矿区上轮流竞价或选择目标；同一矿区只能成交给一家公司。
2. 竞价最小步长、倒计时与保证金必须在界面显示。
3. 出价不能超过当前可支配现金；被占用保证金暂时冻结，失败后解除。
4. 成交时只扣实际中标金额，不允许竞拍保证金与成交额重复扣费。
5. 若玩家没赢得目标地块，允许竞拍剩余地块；必须至少存在一个可负担的保底开采选项以防软锁。
6. 获得开采权后进入本轮矿区经营，不能在开局后任意跨地区侵占 AI 已竞得地块。

**策略意义**：土地/矿区评分并不等于稳赚；高估值、距离、重力和建造成本需要共同纳入回报预期。

## 4.3 竞拍 AI 个性

| 财团 | 风格 | 主要行为 |
|---|---|---|
| 赤曜矿业 | 资源激进派 | 愿意为储量高、稀矿丰富的矿区支付溢价，但有资金上限 |
| 星环运输 | 物流效率派 | 偏好航程短、运输效率高、靠近星港的矿区 |
| 银穹资本 | 股权/套利派 | 更重视股份与资金留存，可能放弃高价矿区 |

AI 不应知道玩家不知道的真实矿物分布。其出价可以依据公开信息、已有侦察等级和少量风格噪声计算。所有竞争行为必须能从存档种子重现。

## 4.4 股份拍卖与胜利路线

- 每轮结算后提供一次星域贸易公司股权拍卖（原型假定每批 5%，20 轮合计 100%）。
- 玩家与 AI 可以选择投入资金、弃权或按上限自动出价。
- 股份在战役内永久归属，不能因为一次单局破产被无提示清零。
- 战役结束时**持股最多者胜出**，若并列则比较净资产；本规则需要通过战役模拟确认玩家具有合理胜算。
- 股份不生成复杂的日度股息系统（首发），避免与采矿收益叠加破坏经济平衡；可以在高级版本增加有限股息。
- 矿区拍卖与股份拍卖使用不同颜色、图标、法律意义和结算信息，避免玩家混淆。

## 4.5 银行、情报酒馆与商业交易

- **银行**：贷款本金、利率、应还日期、罚息、抵押物可见；贷款在单局结束时可结清或跨回合滚动，受授信额度约束。
- **酒馆情报**：以确定价格购买某块矿区的资源评级提示、天气提示或市场预测；信息有可靠度标记。
- **酒馆商业协议**：支付费用获得单轮特定买方最低收购价、较低贷款利率、运输许可优惠等。
- **特殊发现交易**：稀有遗物可以出售换钱或交换永久情报，但不能重复领取同一奖励。
- **可选小游戏**：骰子、纸牌等只作为延期内容；不影响主要经济循环完成度。

# 5. 星域、勘探与矿体生成

## 5.1 资源类型及用途

| 资源 | 角色 | 基础策略定位 | 首发 |
|---|---|---|---|
| 铁钛矿 | 大宗基础资源 | 储量大、低单价、对运输容量敏感 | 是 |
| 晶硅矿 | 中价值工业原料 | 中等储量、价格波动更显著 | 是 |
| 星能晶 | 稀有能源 | 储量少、可出售或触发特殊能源交易 | 是（在第三星域解锁） |
| 异相矿 | 高价值稀矿 | 距离远、难采、单吨收入高 | 是（第四星域解锁） |
| 水冰 | 燃料/冷却资源 | 低售值但可降低深空作业成本 | 扩展优先 |
| 熔核晶 / 地热矿 | 特殊能源 | 提供设施加速和加工机会 | 扩展 |
| 古代遗物 | 特殊收藏/情报 | 主要用于局外交易，不按普通吨位出售 | 扩展 |

采用“图标 + 颜色 + 名称”三重识别，不让色弱玩家仅靠颜色区分矿物。

## 5.2 矿区生成模型

每轮先为待拍卖的 `MiningLot` 生成公开资源评级和有限情报；每份 `MiningLot` 再从预置模板或随机种子生成若干天体（建议原型先在玩家赢得的扇区内提供 3 颗可交互天体）。每个天体包含：

- `body_type`：小行星、卫星、特殊轨道采场等。
- `cluster_id`：决定背景、环境、基础矿种权重。
- `survey_rating`：竞拍前公开的粗粒度资源评价。
- `gravity_class`、`distance_l`、`hazard_tags`：决定运输、着陆和采矿附加成本。
- `deposit_slots`：可部署采矿单元的位置及其允许覆盖范围。
- `deposits[]`：矿种、真实初始储量、硬度、可采比例、隐藏状态。
- `license_owner`：本轮开采权归属。

必须保证：同一种资源的高储量不一定等于高利润；距离、硬度、设备效率、市场价格和建造费用共同决定可盈利性。

## 5.3 三层勘探信息

| 阶段 | 可见信息 | 使用方式 | 成本性质 |
|---|---|---|---|
| 遥感 | 天体外形、环境标签、资源评级区间 | 竞拍前参考 | 免费或低成本被动信息 |
| 轨道探测 | 主要矿种、总储量区间、部分矿点位置 | 投放无人探测器 | 一次性费用及若干游戏日 |
| 近场精扫 | 某个插槽/矿点的矿种、剩余量、难度 | 鼠标框选或部署采矿机器人 | 付费、短时间操作 |

未知信息应形成有意思的冒险，而不是大量纯随机猜谜。允许玩家以低成本获取最低限度的信息。已经揭示的数据在本轮永久保留。

## 5.4 采矿权与扫描关系

- 竞拍之前只能访问公开遥感等级以及花钱获得的有限情报。
- 竞得开采权后才能进行正式采矿投放。
- 勘探失败不应消耗完整采矿舱成本；已经确认的扫描消耗按规则计费。
- 已购买开采权不因场景切换或加载而丢失。

## 5.5 天体空间交互

- 鼠标单击天体：弹出资源卡；已解锁信息显示数值，未知内容用 `?` 表示。
- 选探测器后拖动到天体：出现预计费用、到达时间、扫描半径；松开进入待确认。
- 已扫描可采矿点：显示清晰的建设落点和采矿范围圈。
- 鼠标滚轮缩放、右键拖动星域、双击已许可矿区聚焦；所有坐标以稳定的世界坐标存储，不以屏幕像素作为经济数据。

# 6. 采矿设备、产出与瓶颈

## 6.1 采矿场景本质

矿场不是“钻井管道主题的石油大亨换皮”。玩家在**天体表面或附近**部署采矿舱、无人机器人、补给设备，看到矿石从矿体进入采矿舱储存，再通过飞船运回基地。

第一版建议**每个矿体 1–3 个可部署插槽**，避免复杂的自由建造网格和寻路系统。资源分布、距离、收益与设备半径仍然能形成选择。

## 6.2 基础采矿设备

| 设备 | 功能 | 约束 | 玩家可见表现 |
|---|---|---|---|
| 侦察无人机 | 发现隐藏矿点 | 有扫描次数/能源费用 | 飞向目标，生成扫描波纹 |
| 采矿舱 | 提供作业平台与初始货仓 | 占用矿体插槽，购买/部署成本 | 投送、减速、着陆、展开支架 |
| 采矿机器人 | 实际从矿体采集资源 | 数量受平台和能源限制 | 钻探头/激光束移动、碎石粒子 |
| 小型仓储模块 | 扩大矿体临时库存 | 占用设备槽或升级费用 | 箱体和填充量可见 |
| 装卸臂/货运接口 | 加快火箭装船 | 受泊位/容量影响 | 集装箱、机械臂搬运 |
| 采矿中继站 | 支持多个相邻矿点 | 覆盖半径与吞吐量限制 | 连接线、无人机穿梭 |

## 6.3 开采公式（方案，不是平衡定值）

每个游戏日的理论产出：

`gross_output_t = sum(robot_base_rate_t_day × equipment_bonus × hardness_factor × uptime)`

实际产出：

`min(gross_output_t, deposit_remaining_t, available_mine_storage_t, effective_loadout_capacity_t)`

其中 `hardness_factor ∈ (0, 1]`，硬质矿体可通过专属科技改善；`uptime` 由供能、天气、故障、维护决定。

- 必须采用**每个游戏时间步扣减储量**，不得用动画帧率直接产矿。
- 仓库满后停止新增产出；不凭空丢矿。若需要“损耗罚款”，仅对明确的事故/非法超负荷行为产生，不制造隐形库存损失。
- 装卸效率慢不直接降低采矿机理论速度，但会使库存拥堵并间接停产。

## 6.4 有意义的采矿选择

1. 高储量但远离基地的矿体 vs 近处小矿体。
2. 用廉价初级机器人慢采 vs 升级昂贵采矿模块。
3. 部署第二套采矿舱提高产量 vs 购买火箭解决积压。
4. 新建货仓等待价格回升 vs 快速出售并扩大设备。
5. 提前撤离回收设备 vs 继续追求剩余低价值矿石。

## 6.5 采矿状态与撤离

统一状态机：`UNSCANNED → SURVEYED → PREVIEW → DEPLOYING → OPERATING → FULL / DEPLETED / PAUSED → RECALLING → CLOSED`。

- `DEPLOYING` 不是完成施工，不能立刻产矿。
- `RECALLING` 时不可同时执行新建造；可回收设备按规则返还残值。
- `PAUSED` 可降低维护费用，但不应产生完整产量。
- `DEPLETED` 仍允许等待最后一趟运输或回收设备。

# 7. 火箭与航天器：类型、性能和组装

## 7.1 设计目标

火箭应成为《星矿大亨》与《石油大亨》最重要的差异之一。但玩家关心的主要是**这条航线用哪种火箭最赚钱**，不是亲自求解轨道动力学。

## 7.2 六种航天器定位（完整规划）

| 航天器 | 主要任务 | 前期资金门槛 | 运营定位 | 开放时机 |
|---|---|---|---|---|
| 一次性轻型运矿火箭 | 小批量往返、应急运力 | 低 | 每趟耗材贵、采购灵活 | 开局 |
| 一次性重型运矿火箭 | 单次大量运矿 | 中 | 载重大、适合短期冲刺 | 中前期 |
| 可回收轻型火箭 | 高频短途重复航线 | 中 | 前期贵、单位航次成本低 | 第二星域 |
| 可回收重型火箭 | 大型矿区主力运输 | 高 | 装载率与维护十分重要 | 中后期 |
| 深空货运飞船 | 远距离中继与批量转运 | 很高 | 高成本资本品，长航程高效率 | 第四星域或扩展 |
| 无人探测火箭 | 侦察与样本带回 | 低–中 | 不能直接承担矿石运输 | 开局 |

首个可玩切片只要求一次性轻型与可回收轻型两种运矿方式、一种探测器。其他类型保留在数据模型和后续平衡表中。

## 7.3 一次性 vs 可回收：游戏化解释与硬规则

**一次性**：表示每次航次的助推/发射级不可复用，需要支付较高发射耗材和替换成本；下行运矿货舱仍然有安全返回机制。不要表现为整艘货船携矿飞回后又“神秘消失”。

**可回收**：发射级/主船完成任务后经过着陆、检修、加注重新进入可用船池。采购价较高、单次运营费用较低；维修、失败概率、复用寿命可能形成成本。

两者都必须能完成基本“去矿区 → 装货 → 回港”循环，但成本结构不同。按轮计算的比较应包含：初始采购分摊、燃料、耗材、检修、失败期望损失、残值、装载率和时间占用。

## 7.4 简化性能模型（先用于原型）

每个火箭蓝图/船型保存：

- `payload_capacity_t`：货舱上限。
- `range_l`：最大可达航程单位。
- `flight_days_outbound / inbound`：基于航程与速度得出的旅行天数。
- `launch_cost_cr`：单次起飞/耗材成本。
- `maintenance_cost_cr`：回港检修费用。
- `turnaround_days`：卸货、检修和再次出发所需时间。
- `reusable`、`reuse_limit`、`recoverability`：复用属性。
- `reliability`：故障风险，但风险应可见且玩家有避免方案。
- `supported_gravity_class`：可服务的矿区重力条件。

**可达性**：航程、重力条件和载货能力满足要求才能建立航线；不能靠 UI 动画骗过引擎校验。

**收益**：`expected_trip_margin = delivered_t × expected_sale_price − launch_cost − fuel_cost − maintenance_allowance − cargo_loss_risk`。

**吞吐能力**：`effective_transport_t_day = capacity_t × expected_load_factor ÷ trip_cycle_days`。

真正决定优劣的是**单位资本占用与单位时间利润**，而不是单看一艘火箭的最大载重。

## 7.5 火箭装配工作台——特色玩法但不阻塞基础经营

**目标**：玩家第一次组装一艘火箭约 30–60 秒（目标值，待试玩）；熟练玩家可用系统预设、一键保存蓝图与批量生产。

**四个首批插槽**：

1. 发动机：推力/能耗/允许载重。
2. 燃料舱：航程/燃料质量。
3. 货舱：最大载矿吨位/自重。
4. 回收组件：可复用能力/载重损失/回收与检修费用。

**交互序列**：组件仓鼠标拖拽 → 合法插槽自动吸附 → 实时显示改变的参数 → 参数合法性反馈 → 保存蓝图 → 购买/生产实例 → 船池中可调度。

**必须避免的设计**：
- 不允许组装只改变外观却不影响运矿经济；至少两种配置在相同条件下的单位时间利润明显不同。
- 不要求每个航次重新拆装；不能强迫非创作型玩家使用拖拽组装。
- 不对玩家隐藏质量、成本与货仓增加后的代价。
- 装配工作台与采矿主场景分离，不占用日常矿场操作空间。

## 7.6 装配合法性

- 必须至少有发动机、燃料舱与货舱。
- 总质量不超过发动机支持的发射质量上限（游戏化公式）。
- 燃料预算必须覆盖选择的航线；不足时给出差额。
- 回收组件只允许与兼容的发动机/结构配对。
- 所有组件购置费用仅在“生产实体火箭”时扣除；编辑蓝图免费。
- 非法设计不能保存为“可生产蓝图”，但可保存为未完成草稿。

## 7.7 火箭画面与动画承诺

最少的有效演出链路：发射前准备灯 → 点火火焰 → 火箭离开发射台 → 航线飞行动画 → 采矿点停靠及装货 → 返回 → 可回收火箭着陆/一次性发射级损耗提示 → 卸货。

玩家可选择：完整演出（首次推荐）、精简演出、直接跳过。任何模式下经济结果必须完全一致。

# 8. 船队调度、航线、仓储与时间

## 8.1 船队状态机

建议以 `IDLE → PREPARING → OUTBOUND → DOCKING → LOADING → INBOUND → UNLOADING → MAINTENANCE → IDLE` 为标准状态流程。

可选异常状态：`WAITING_FOR_CARGO`、`WEATHER_HOLD`、`DAMAGED`、`LOST`。异常必须有清晰通知，并避免一艘船同时存在两个互斥阶段。

## 8.2 自动调度和手动干预

- 玩家默认可以对矿区建立固定航线：矿区 A → 贸易港 X，配置船型和最低发车装载率。
- 初期允许手动拖动一艘空闲火箭到矿区；熟练玩家可以设自动往返。
- 正在航行的飞船不能凭空瞬移改派；只能排队等待下一个可修改节点。
- 自动运输应尽量减少“矿舱满了，玩家要频繁点按钮”的重复操作。
- 支持暂停、恢复、临时停靠、切换目的港，但要明确剩余运输时间和费用。

## 8.3 发射窗口

- 标准窗口随时可使用但可能成本较高。
- 最优窗口需要等待，但燃料或风险更有利。
- 紧急窗口能更快出发但费用更高。
- 玩家在界面中能直接看到“等待 × 天、节省 × Cr、可能损失的经营时间”。
- 天气/窗口的变化应提前预告或展示概率范围。

## 8.4 真实库存位置

至少区分：`mine_stock`（采矿舱）→ `ship_cargo`（在途）→ `port_stock`（贸易港仓库）→ `sold`（已售）。

**硬性守恒**：正常运输时，矿石不会凭空出现或消失；转移库存必须原子完成。一吨货不能既算矿区库存又算在途货物。

- 装载时矿仓减少、船仓增加。
- 卸载时船仓减少、港仓增加。
- 出售时港仓减少、现金增加。
- 事故损耗须有单独日志，标明原因与数量。

## 8.5 吞吐瓶颈

采矿、矿仓、装载接口、飞船载重、发射间隔、港口泊位、贸易商日收购额度应构成可见的供应链。

瓶颈 UI 只指出**当前第一瓶颈**及建议行动，不同时弹出五种问题。示例：“晶硅矿仓 95%：当前运输可清理 45 t/日，产量 70 t/日。建议增派货船或提升装载效率。”

## 8.6 经营时钟及一局结算

原型时间建议：

- 一局为 30 游戏日。
- `1×` 速度每游戏日对应 30 现实秒（约 15 分钟自然时长，不含暂停）。`2×`、`4×` 按倍数加速；可暂停。
- 引擎最小模拟步长可以保持原工程的 **0.5 游戏日**，表现层使用插值模拟连续动画。时间步长更改须经过全部经济测试。
- 经营期限到达 D30 时自动暂停，生成结算快照。
- 已起飞但未抵港的矿石按**明确的清算规则**处理：建议首版提供“自动运回（扣除固定清算费用，按结算参考价销售）”而不是凭空丢货；最终规则需要专项平衡测试。
- 提前结算允许，但需满足“无进行中的待确认经济操作”，未回港资产按相同公开规则清算。

# 9. 贸易市场、择价与特殊能源

## 9.1 两家基本买方

- **晨曦贸易商**：价格较平稳、收购额度相对稳定。
- **赤曜工业联盟**：价格弹性更大，特定矿物可能出现高价，额度可能有限。

二者可在每个游戏日独立变价。玩家可切换贸易港、暂存货物或接受限时订单。

## 9.2 价格模型（提案）

`quote_price = base_price × market_cycle_factor × local_supply_demand_factor × event_factor`。

建议对结果设置最低/最高区间，避免零价或无限涨价；报价更新需要可复现的随机种子。不同矿种和买方具有不同价格波动速度、购买配额和需求偏好。

**重要交互**：卖方报价旁不只显示“当前价格”，还显示过去一段时间的简单曲线、可出售库存、当日交易配额、预计收入。

## 9.3 玩家可选销售策略

1. **立即出售**：货物到港按当前价尽快卖，优先现金流。
2. **目标价出售**：仅当报价达到玩家设定阈值时自动卖，否则储存。
3. **手动保留**：玩家选择时机集中卖，承担仓储成本、时间耗尽和价格回撤风险。

可添加两种处理：部分出售和清仓。必须显示实际成交量，买方额度不足则保留剩余库存，不得以超过额度的幻想价格结算。

## 9.4 特殊能源对标《石油大亨》的天然气策略

原作后期利用天然气影响收购价格。《星矿大亨》改成**星能晶 / 能源合约促销窗口**：

- 玩家在稀有天体中发现星能晶。
- 可以立即卖掉星能晶，或者储备供给特定贸易商的能源订单。
- 满足能源订单条件后，该贸易商在一定期间对某类矿石提供溢价或额外收购额度。
- 溢价作用范围、时间、触发成本全部公示；不能让玩家以无成本方式无限重复抬价。
- 高级科技解锁能源储存、转换、提前部署和合约时长等策略。

关键是**有准备成本、有触发时机、有集中兑现的收益**，而不是必须以物理方式“天然气吹管道”。

## 9.5 合同与保底价

- 酒馆或贸易商可提供当轮保底收购价合同。
- 高阶合同可以含有指定矿种、截止日期、保底量、保证金、违约损失。
- **首个可玩切片不要求复杂违约合同**，只需两家买方的普通交易和一个保底价演示。
- 合同货量应占用库存预留，不能同一批货重复承诺给多个买家。

# 10. 财务、成本、贷款与收益计算

## 10.1 所有权和统一账本

至少三项独立口径：

- **可支配现金** = 现金余额 − 已冻结竞拍/合同保证金。
- **本轮经营利润** = 已确认营收 − 本轮可归属的费用与折旧（折旧细则可在首版简单化）。
- **净资产（战役记录）** = 现金 + 可变现资产估值 − 贷款本金及负债。

不能把“买火箭”同时算现金支出和当期全额经营亏损之后，又在净资产中重复减去设备价值。现金流和利润必须明确区分。

## 10.2 费用分类

| 成本 | 发生时点 | 玩家控制点 |
|---|---|---|
| 采矿权拍卖价 | 竞拍成交 | 是否抬价争地 |
| 探测器费用 | 确认勘探命令 | 多扫还是冒险部署 |
| 采矿舱/机器人购置 | 确认建造/生产 | 投资产能 |
| 火箭采购/部件 | 购买实体火箭 | 一次性和可回收投入差异 |
| 发射耗材与燃料 | 每次航次确认/执行 | 航线、窗口、载重 |
| 检修与维护 | 完成回收或按时间步 | 高频利用与安全余量 |
| 仓储/泊位 | 每时间步或购买时 | 囤货多少、是否扩容 |
| 银行利息 | 游戏日/回合结算 | 贷款额度和还款时机 |
| 事故损耗 | 有明确事故时 | 保险、天气窗口、设备升级 |
| 股权竞拍价 | 股权中标 | 当前收益与终局胜负取舍 |

## 10.3 核心决策指标

- `unit_net_margin_cr_t = expected_sales_cr_t − effective_mining_cr_t − logistics_cr_t`。
- `capital_return_rate = expected_round_profit / capital_employed`。
- `ship_load_factor = delivered_t / potential_capacity_t`。
- `mine_utilization = actual_output_t / theoretical_output_t`。
- `payback_trips = ceil((reusable_upfront − disposable_upfront) / (disposable_trip_cost − reusable_trip_cost))`，仅在分母为正且比较条件相同时有效。

UI 不必把这些公式全给新手看，只显示关键的“预计利润/趟、预计回本趟数、当前首要瓶颈”。

## 10.4 财务困境与恢复机制

- 新手开局不得背上无法理解的巨额债务。
- 资金不够时可等待已有运矿收入、出售部分设备、请求有限贷款或降低下一轮投资规模。
- 若现金不足以支付日常维护，游戏先自动暂停并显示三条建议，而不是静默继续亏损。
- 只在可理解的条件下触发破产/重整；保证可以从首轮失败中恢复，战役模式提供重新挑战当前回合的非惩罚性选项（成就/排行榜可标记重试）。

# 11. 科技升级、星域成长及长期经营

## 11.1 升级结构

分为五个功能组：

| 系统 | 升级示例 | 对玩家可见的收益 |
|---|---|---|
| 探测 | 扫描半径、探测速度、远距识别、稀矿筛选 | 用更少钱发现更多有价值资源 |
| 采矿 | 采矿速度、硬矿钻头、设备作业半径、矿舱容量 | 提高同一矿体可采吨数与效率 |
| 火箭 | 发动机、货舱容量、燃料效率、回收技术、检修效率 | 运输成本下降、航程和载重提高 |
| 商业 | 港口仓储、装卸速率、价格锁定、贷款优惠 | 减少拥堵，改善市场操作空间 |
| 特殊工业 | 星能晶利用、熔岩能源、水冰补给、精炼 | 打开后期新策略 |

## 11.2 解锁原则

- 第一星域仅开放能解决实际问题的 5–7 项升级。
- 每一项升级都要能在下一轮明确感知效果（更快扫、更大仓、成本更低、能挖硬矿等）。
- 科技升级不能只添加 3%/5% 微小数值变化而毫无可见反馈。
- 不允许大量不同科技叠加导致运输效率无限增长或价格突破合理上限。
- 新科技可以解锁某种全新决策，但每一星域至多引入 1–2 项陌生的核心机制。

## 11.3 持久成长与单局隔离

**跨回合永久保留**：现金/负债、已购买科技、已持有股份、已解锁蓝图、部分永久火箭资产（需定义维护/折旧规则）、战绩与成就。

**单回合重置**：本轮矿区采矿权、局内天体资源储量、临时采矿舱和普通库存（按结算规则处理）、临时交易事件和局内剩余时间。

注意：如果永久保留整支巨型舰队，会造成后期经济滚雪球过快。可在战役中引入有限船池、维护费或分星域部署成本，但不得无提示没收玩家资产。

# 12. 竞争财团 AI、竞拍与市场行为

## 12.1 AI 必须竞争，而不是代替玩家玩游戏

战役默认有三家 AI 财团（第 4.3 节）。其作用是制造**机会成本和可读的竞争压力**，而不是追求复杂到不可理解的通用经济智能。

| 机制 | 输入信息 | AI 决策 | 玩家可见证据 |
|---|---|---|---|
| 矿区竞拍 | 公开评级、距离、环境、已知历史评分、现金余额 | 目标估值、最高愿付价、是否退出 | 竞价过程、竞拍后的解释摘要 |
| 股份竞拍 | 当前持股、可支配资金、剩余轮次、当前股价 | 是否保留现金或争夺股份 | 出价记录、最终持股变化 |
| 单局经营 | 所得矿区特征、AI 的永久升级与船队档次 | 生成有约束的经营结果 | 单轮利润、事故、采矿率与成本摘要 |
| 酒馆交易 | 自身资金和本轮可能的优势 | 购买少量协议或情报 | 对手经营回顾，不泄露隐藏数据 |

首发阶段对手单局经营可以使用**与玩家同口径的简化模拟**，不需要同时渲染三套实际矿场；但不能从无到有获得资金、股份或矿产。对手现金、支出、竞拍获胜和单局收益必须在账本上守恒。

## 12.2 可预测性、公平性和难度

- AI 只依据本方允许获取的情报进行估值；不读取未揭示的实际储量。
- `ai_strategy` 可设为资源激进型、物流效率型、资本保守型；风格影响估值权重，不影响规则豁免。
- AI 预算必须覆盖竞价保证金、当轮基本开发资金与股份竞争预算；不能无限抬价。
- 低难度优先降低 AI 对资源的估值精度和出价幅度，而非偷偷增加玩家产出；高难度改善决策但不作弊。
- 同一随机种子 + 同一输入序列，竞拍和单局结果必须可重复。
- 当玩家连续两轮没拿到矿区时，设计上提供清楚的后备路径（可负担地块、银行融资或重新竞拍），避免卡死。

## 12.3 单局对手结果的审计

对手结果记录 `land_cost, survey_cost, mining_cost, flight_cost, sale_revenue, debt_interest, round_profit`，供结算界面和测试器使用。**AI 不可直接生成“利润 +50,000”而无对应收入和成本。**

# 13. 特殊资源、星域环境与内容扩展

## 13.1 首发四星域的差异必须改变决策

| 星域 | 首发新增的核心挑战 | 新资源或设施 | 典型决策 |
|---|---|---|---|
| 晨曦边境 | 基础信息不足、距离和储量权衡 | 铁钛矿、晶硅矿；一次性轻型运矿火箭 | 多花钱扫描，还是尽快部署？ |
| 赤沙带 | 矿体硬度与设备效率损失 | 硬矿钻头、可回收轻型火箭 | 升级钻头，还是抢占高品质近矿？ |
| 霜环群 | 发射窗口、有限港口额度、能源交易时机 | 星能晶、能源订单、保价协议 | 囤货触发溢价，还是保住现金流？ |
| 幽光深空 | 远航、贵重稀矿与高资本占用 | 异相矿、重型火箭或长航程船型 | 多批短途运输，还是一次远距重载？ |

**首发与扩展边界修订：水冰/燃料补给属于扩展优先项，不是星域 III 首发通关所必需的机制。** 星域 III 首发依靠能源订单与发射窗口建立差异。

## 13.2 《石油大亨》本体机制的功能性映射

| 机制类别 | 原作策略功能 | 本作对应 | 首发状态 |
|---|---|---|---|
| 四个地区/分阶段障碍 | 逐步增加系统难度 | 四个星域、环境限制与科技解锁 | 必须 |
| 天然气与价格操纵 | 通过准备和择时集中兑现收益 | 星能晶供能订单/临时市场溢价 | 必须（III 星域） |
| 稀有发现/宝石 | 给勘探带来额外奖励与情报交易 | 宇宙遗物/稀有样本 | 扩展，首发可留一个教学事件 |
| 酒馆好处与特殊服务 | 以资金交换信息或交易优势 | 情报酒馆、保价、融资优惠 | 必须（精简 2–3 种） |
| 银行贷款 | 融资与偿债取舍 | 星际授信、利息、还款 | 必须 |
| 技术投资 | 永久改善未来轮次表现 | 探测、采矿、运输、商业升级 | 必须 |
| 股份拍卖 | 在收益和最终胜利之间分配资本 | 星域贸易公司股份 | 必须 |

## 13.3 扩展内容完整预留

此处是**设计储备**，不是首发必做清单：

1. **熔岩生态**：高温矿体、耐热采矿舱、热能转化、热量提高加工效率；有额外能耗与故障风险。
2. **水冰资源**：冷却剂与推进剂，降低特定航程费用；受采集设备和转化能力限制。
3. **精炼体系**：矿石 → 高纯合金 / 推进剂 / 晶体元件，按清晰产出率加工；不在首发引入多层工厂链。
4. **特殊探险**：限定燃料、时间、装备的深空远征，获得珍贵物品或股权奖励。
5. **岩层爆破**：定向破岩器，可打开难采矿点，需支付一次性费用并承担明确范围限制。
6. **遗物收藏与情报**：收集品只提供有限长期奖励，不允许叠加成无限经济增幅。
7. **酒馆小游戏**：若加入，需要有非赌博式替代路径，且不阻挡主要战役流程。
8. **多人竞拍**：可异步轮次；所有核心玩法仍在单机完成，不绑定服务器存档。

## 13.4 内容规模预算（策划目标）

首发建议 4 个星域、每星域 5 回合、4 种主要矿物、2 个常规买方、3 家财团、2–4 个可用基础运矿船型、12–18 项明显有感知的永久升级、少量事件模板。所有数量均可根据垂直切片反馈减少；**不以 20 项科技或几十个矿星作为完整感的替代品**。

# 14. 界面、信息架构与直接操作 UX

## 14.1 界面分区（仅保留三个主要空间）

**A. 总部**：场景化入口，进入拍卖、银行、工坊、火箭车间、酒馆、战绩和出发准备。每次只展开一个主要交易界面。

**B. 太空采矿主场景**：基地/星体/飞船/航线占主要空间；顶栏只保留资金、日期、速度、阶段任务；底栏优先展示探测、部署、航线、交易和更多；选中对象才打开右侧详情。

**C. 火箭装配车间**：独立拖拽组装视图，左侧零件仓、中部装配架、右侧性能/成本校验；预设船型允许跳过装配。

结算、单局市场价格详情和升级是模式化子页面，不必作为同时常驻的第四、第五主视图。

## 14.2 六个需要单独验收的核心页面

| 页面 | 玩家刚进入时最需要看见 | 一个主要操作 | 核心反馈 | 不应长期显示 |
|---|---|---|---|---|
| 总部 | 当前现金、持股、下一轮主要选择 | 选择设施/事件入口 | 选择可用/不足的原因 | 实时矿场 10+ 项 KPI |
| 矿区拍卖 | 地块卡、已知情报、剩余现金、AI 当前出价 | 竞价/退出 | 预算和归属变化 | 科研树、合同详情 |
| 太空采矿 | 天体、采矿舱、飞船和当前目标 | 探测或拖动部署 | 实际设备动作与库存变化 | 完整财报、大型技能树 |
| 火箭组装 | 当前火箭实体、零件槽和参数 | 拖动组件吸附 | 航程/载重/成本增减 | 贸易商图表、财团排名 |
| 市场 | 两家报价、数量、港仓库存 | 定量出售/自动策略 | 已成交量与到账现金 | 无关星域地图和科技 |
| 单局结算 | 净收益、来源与瓶颈、对手结果 | 返回总部 | 与上一轮比较 | 新采矿按钮 |

## 14.3 关键鼠标手势规范

- **左键单击**：选择/聚焦；不自动扣钱。
- **左键拖拽**：只用于拖入探测器、采矿舱、货运飞船、火箭组件或规划航线；手势结束生成预览。
- **右键拖拽**：平移场景；**滚轮**：以指针为锚点缩放。
- **右键单击 / ESC**：取消当前未确认操作，优先级高于退出页面。
- **双击天体**：聚焦、展开详情，不默认建立经济交易。
- **确认按钮**：显示费用、时间与主要影响；成功后返回场景并触发动画。
- 所有拖拽必须有**点击选择 + 点击目标**的无拖拽替代途径；不得只支持高精度鼠标。

## 14.4 一屏信息密度预算

建议在 1920×1080 设计分辨率下：主场景 70–80% 可视宽度；顶栏高度约 52–64px，底部快捷栏约 60–76px；详情侧栏宽约 300–380px，只有选中对象时出现。**这是布局目标，不是固定像素强制值。**

优先级顺序：当前目标 → 正在操作的对象 → 运输/库存瓶颈 → 资金和日期 → 中长期指标。高层财务、科技和合同不抢主场景视觉焦点。

## 14.5 教程和提示的严格规则

- 首轮只教五个动词：`发现 → 部署 → 运输 → 出售 → 升级`。拍卖和股份在完成首次收益后渐进教学。
- 单屏只保留一个主要目标；重要目标必须能一键聚焦对应天体或设施。
- 当操作失败，消息格式为：“**原因** + **需要什么** + **如何解决**”。如“燃料不足，无法执行 4L 航线；还需 +1.2L 航程，升级燃料舱或改派近距离矿区”。
- 玩家完成该教程步骤后不重复弹出相同遮罩。看过的说明可从帮助面板回放。
- 玩家可以跳过教程；跳过只改变引导，不改变资金或经济规则。

# 15. 美术、动画、音效与性能（Art & Animation Bible 摘要）

## 15.1 视觉目标和非目标

采用**清晰、可读的高精度 2.5D 工业科幻**，优先保证规模、材质、光照和动作的一致性。科技元素用于表达状态，不应让满屏 HUD、扫描线和发光边框掩盖游戏场景。

可参考成熟策略游戏的**构图原则与动效层次**，但不得直接复刻他人的游戏截图、角色、纹理、音效或 UI 资产；所有资产须有来源及许可记录。

- 主色：深空蓝黑、钛合金灰；信息强调：青蓝；作业动作：工业琥珀；风险：橙红；可用/收益：适度绿色。
- 明暗：场景中天体、基地和矿机应具有实体明暗层次；信息发光使用局部光，不以全屏白雾提高“画质”。
- 设备识别：轮廓、发光灯位和标识在 1080p 缩小至 75% 时仍清楚。
- 资源识别：矿物颜色 + 图标形状 + 文字三重编码；不得只靠色相判断类别。

## 15.2 动画必须对应真实状态

| 行为 | 动画状态与连续性 | 对玩家必须表达的信息 |
|---|---|---|
| 探测 | 出发 → 飞行 → 扫描扇区/波纹 → 返回/完成 | 覆盖哪些矿体，扫描是否完成 |
| 采矿舱 | 运输落点 → 减速着陆 → 展开机构 → 作业 | 设备已从未部署变为可采集 |
| 采矿机器人 | 寻找矿面 → 开钻/切割 → 碎石/矿流 → 回仓 | 矿石确实在产出；矿仓满则停机 |
| 货运火箭 | 备货 → 点火 → 上行 → 对接 → 装载 → 下行 → 卸货 | 当前物流状态、可用时间、任务目标 |
| 可回收火箭 | 返回 → 降速点火 → 着陆 → 检修/加注 | 成功复用与尚需维护的时间 |
| 一次性火箭 | 发射级分离/消耗，回收货舱/载具返航 | 明确为何每次有耗材成本 |
| 股份竞拍 | 报价更新 → 对手退出 → 成交 → 持股变化 | 股权归属与预算变化 |
| 交易 | 选择港仓库存 → 成交订单 → 货物减少 → 现金增加 | 确认成交吨位与实际金额 |

- 动画**不可负责经济运算**：只响应已确定的状态事件；跳过演出不会改变收益。
- 首次发射演出可完整展示（建议 6–10 秒），后续默认精简（约 1–2 秒），玩家可选择全部跳过。
- 持续性动画至少包括采矿工作循环、货船移动、矿仓装卸反馈；不能只有点击后的“闪一下”。
- 防止假反馈：没成功扣费时不能出现已建造钻机；货物没到港不能提前出现到账动画。

## 15.3 动效分级和可访问性

- **基础**：只保留状态切换、进度条和低负荷动画。
- **标准**：增加火箭尾焰、粉尘、矿脉粒子、光照过渡与适度相机运动。
- **高**：更细的粒子、尾迹、动态灯光与局部后处理；仅在设备性能允许时启用。
- **减少动态效果**：关闭镜头抖动、闪烁、强烈拖影及自动大幅缩放；保留信息性提示。
- 色弱、字体大小和字幕应有基础支持；声音不是唯一信息渠道。

## 15.4 音频反馈层次

- **环境**：深空底噪、基地机械氛围、设备低频运行；不可在每个菜单播放刺耳的循环声。
- **交互**：选中、合法吸附、错误拒绝、确认付款、交易成功，以短音效表达状态。
- **事件**：火箭点火、助推分离、着陆回收、稀有发现、拍卖成交，具备明显辨识度。
- **音乐**：经营期平稳、竞拍期紧张、结算期放松；可关闭且不遮盖关键音效。

## 15.5 建议性能预算

目标桌面 1920×1080：建议中端设备维持平均 60 FPS，低端设备有 30 FPS 降级选项；需要在目标机器上实测确认。场景中可同时存在多个小型天体、少量可见采矿舱和在途船只，避免为视觉效果建立不必要的高精度三维模拟。

建议用 Godot 4.x 2D `CanvasItem` / `Node2D` / `Control`，状态动画使用 `AnimationPlayer` / `Tween`，多粒子用 `GPUParticles2D`，复杂星云可用轻量 Shader；尽可能选择单一主后处理、控制 draw calls，并让 offscreen 设备停用高频视觉刷新。

# 16. 经营规则边界、结算与胜负

## 16.1 单回合结算顺序（必须固定）

在 D30 截止或主动结束经营时，按**同一确定顺序**执行：

1. 阻止新的经济命令，冻结所有新增竞拍/出货/建造申请；完成已经被确认且可原子完成的操作。
2. 按统一模拟步长推进至截止时刻；停用新的采集与发射指令。
3. 处理在途矿石、矿仓库存、港仓库存和已接受合约：根据公开清算规则计算可售额与费用。
4. 结算借款利息、已产生的维护费用和应承担的事故损失。
5. 确认本轮收入与支出、现金余额、经营利润、资产变动和清算明细。
6. 归还本轮租赁/临时设备，按残值规则回收可回收资产，保留应继续存在的永久蓝图、科技和股份。
7. 生成只读结算快照，计算本轮成绩、AI 竞争结果与可用的总部资金。
8. 回到总部，允许独立参加股权竞拍或配置下一轮科技与购买计划。

**关键规则**：股权拍卖不在矿区经营过程中发生；矿区开采权拍卖在下一轮经营开始前发生。玩家必须始终知道此刻花钱会不会挤占下一场股份拍卖。

## 16.2 清算规则（需要测试的默认方案）

- `port_stock`：在当轮最后的公开参考价格下清算，受买方剩余额度约束；未卖出部分进入强制折价回购（折价率显示）。
- `ship_cargo`：以预计回港扣除剩余运输费用和清算折价后结算，只有明确的货运事故才允许损失。
- `mine_stock`：若本轮有合理运力预计可运出，则按保守运费和折价回购；否则按废弃残值/零变现处理，不能自动按港口价格卖出。
- `reserved_stock`：先解除不再履行的预留，再按违约规则扣除保证金，不能重复卖掉。
- 任何资产和货物都需要在结算表明示数量、单价、折价、费用。

上述自动清算是**建议初值**。如果测试表明玩家会故意在末日积压，靠强制清算套利，必须降低残值或调整剩余航次规则，而不是隐藏修改价格。

## 16.3 战役股权胜负

- 战役原则上共 20 个回合，每回合 5% 股份进入市场，累计 100%；股票全部由玩家或三家 AI 拥有，不得超发。
- 战役结束按持股数比较，最高者胜出；若最高持股并列，则用净资产、再用现金决定名次。没有股权达到 50% 也可胜出，**不是必须绝对控股**。
- 记录每一批成交的持有者、竞价与金额。无理由改变归属不可接受。
- 提前终局仅在玩家的股权领先已经数学上无法被追平时可以触发，或维持固定 20 回合给玩家完整体验；默认固定 20 回合。

## 16.4 资金断裂、重试与失败

- 本轮无法支付必要成本时允许暂停、出售部分实体设备、取得限额融资或退出本轮；失败不得导致负库存或负现金继续采购。
- 经营失败不抹掉已经合法获得的永久股权、科技、蓝图；贷款逾期应按照可见规则限制新投入。
- 如果失去开采权且没有资金进入下一局，战役提供一次清晰、成本受限的恢复路径，不允许无限免费补助刷钱。
- 重试当前回合会回滚至**该回合开始前的完整存档快照**，包括 AI 竞拍状态、随机种子、现金、股份、科技和火箭资产，避免“保留失败损失却重置收益”的漏洞。

## 16.5 存档及状态隔离

- 必须支持总部准备、竞拍结束、经营中、结算前、结算后三类以上明确存档阶段；读取时恢复相应阶段，不重复发放奖励。
- 未完成动画可在载入后以当前经济状态恢复场景，无须逐帧恢复烟雾等纯视觉对象。
- 本游戏存档必须拥有独立的 `frontier` 命名空间、阶段快照和 schema 版本。

## 17.5 多 AI 文件所有权与分支纪律

- **整合/架构 AI** 独占修改主入口、跨模块接口、数据 schema 和 CI；所有领域改动以独立 PR 合并。
- **玩法 AI（星系/采矿）** 负责星域生成、勘探、部署与采矿规则；不改市场账本。
- **玩法 AI（航天/经济）** 负责火箭状态、费用、库存转移和交易规则；改变共用契约需先走架构 AI 审查。
- **交互 UX AI** 负责新场景与直接操作；不得从 UI 脚本直接修改现金、库存和矿体储量。
- **视觉 AI** 负责设备动画、火箭演出、场景 Shader 和音效；必须有独立 Demo 和性能预算。
- **QA/平衡 AI** 负责每轮经济仿真、异常状态和存档回归，不能仅靠“Godot 能打开”判定完成。

所有 AI 从冻结的**同一基线提交**创建分支；每项任务附截图/GIF（如有）与测试报告；不能无审批改动别的目录。当前 `main_screen.gd` 与 `v40_dawn_engine.gd` 是高冲突文件，非整合 AI 不应并行修改。

# 18. 垂直切片（Vertical Slice）：首个可验收经营闭环

## 18.1 范围冻结（MVP 切片）

**目标**：一局从总部准备到结算的 10–20 分钟可玩原型，最终正式单局是否达到 15–25 分钟再由试玩评估。

**必须包含**：

1. 一个简化总部界面，显示现金、进入矿区拍卖入口与两种基本升级。
2. 三处候选矿区、一个可读的 AI 对手，以及一场真正影响现金的采矿权竞拍。
3. 一张可见的太空采矿地图：基地 + 三颗可选矿体，至少两种矿石。
4. 一次可拖拽的勘探部署；一次采矿舱拖拽投放和自动采集动画。
5. 两种策略不同的货运方案（一次性轻型与可回收轻型），可分配航线并实际看到发射和返航。
6. 一套位置化库存转移：矿舱 → 船舱 → 港仓 → 售出。
7. 两家独立变价的贸易商，支持立即出售和保留货物。
8. 倒计时、结束和完整利润结算；收益回到总部后可投资升级。

**明确不做**：完整火箭自由组装、长期集团资产模拟、四星域全部内容、多层精炼、多人联机、复杂 AI 长期策略、遗物收藏、全量研究树。火箭组装作为独立 UX 演示，不阻塞经营切片通过。

## 18.2 最小可玩脚本（玩家视角）

| 玩家时间 | 玩家意图 | 可观察场景变化 | 相关系统 |
|---|---|---|---|
| 0:00–1:30 | 了解当前目标，投标获取矿区 | 地块归属、剩余现金 | 拍卖/总部 |
| 1:30–3:30 | 发射探测器确认矿石 | 探测器飞往天体、扫描完成 | 勘探 |
| 3:30–5:30 | 拖放采矿设备 | 实体设备落地、机械臂展开 | 采矿 |
| 5:30–8:00 | 指派火箭，看到首次卸货 | 飞船飞行、矿石装载量减少、港仓增加 | 运输 |
| 8:00–12:00 | 观察两家报价并卖出 | 成交量、金额、价格曲线 | 市场 |
| 12:00–18:00 | 应对瓶颈/等待时机并结束 | 库存变化、结算与下一轮按钮 | 综合经营 |

以上是**引导路径及时间预算**，不是强制锁定玩家动作或确保每个玩家都在指定分钟结束。

## 18.3 切片验收标准（必须客观可测）

- 新玩家在无口头说明的情况下能找到“第一步做什么”；若超过 2 分钟仍无头绪则记录为引导失败。
- 玩家能完成一次勘探、一次采矿部署、一次发射、一次卸货和一次出售，并看到相应动作。
- 玩家不必进入三个以上深层菜单，就能完成一趟运输交易。
- 在无作弊的情况下，至少有两种有可解释差异的经营策略能带来不同结果（如短航线一次性 vs 长期可回收，早卖 vs 囤货）。
- 连续 100 局固定种子自动模拟：不得出现负库存、负债账本错记、重复出售同一吨矿、重放奖励、竞拍保证金重复扣款。
- 必须能在拍卖前、经营中、结算后存档并恢复；同一种子恢复后的经营结果一致。
- 至少在两种分辨率（1920×1080、1280×720）检查布局，无关键按钮被遮挡；输入状态在拖拽、取消和切屏后不失控。
- 发射、设备运行和交易动作至少有清楚的视觉/音频反馈；动画跳过不影响账本。
- 首次玩家测试的主要问题都有记录和优先级；不以“所有开发者都觉得能玩”为验收依据。

| M3 视觉切片 | 一套统一天体/设备/火箭美术与连续动画 | 视觉表达与真实状态一致，性能达标 | M2 |
| M4 战役成长 | 股权竞拍、贷款、升级、四星域与 AI 对手 | 可从第 1 轮玩到战役结局 | M3，可并行准备数据 |
| M5 火箭工坊 | 拖拽组件、合法性、蓝图、采购、复用回本 | 组装影响运输经济且可跳过 | M1 的船型成本模型 |
| M6 发布打磨 | 内容、音频、可用性、平衡、错误修复、打包 | 发布清单完成，首发范围冻结 | M4+M5 |

**排期原则**：任务按可验收闭环拆分；不在 GDD 中承诺未经评估的完成日期。风险点优先顺序：玩家看不懂 → 核心不好玩 → 经济失衡 → 功能与视觉兼容 → 内容不足。

## 19.1 推荐的首批四个独立开发任务

- **任务 A（UX）**：制作 `field_operation` 灰盒界面，只有基地、天体、目标提示、底部四按钮、选中详情；支持单击与拖拽预览。交付可运行 `.tscn` 和操作录像。
- **任务 B（核心规则）**：实现独立 `frontier` 单轮状态、矿区竞拍和回合结算；不得影响新项目其他领域的现金权威账本。交付经济不变量与头less 测试。
- **任务 C（采矿/航天）**：把采矿舱、火箭运力接入统一库存链路；先使用两种固定火箭，不做完整装配。交付可完成首次运输的端到端测试。
- **任务 D（表现）**：创建可独立运行的勘探飞行、设备展开、采矿循环、火箭发射/卸货视觉原型；没有真实资产时使用清楚的灰盒形体。交付动画事件协议。

**四项任务并行时，GameKernel/SharedContracts 的接口变更必须由整合 AI 统一合并。**

# 20. 测试与质量保证

## 20.1 自动化测试矩阵

| 类型 | 关键测试 | 通过标准 |
|---|---|---|
| 引擎单元 | 勘探信息、矿产生成、采矿产出、火箭可达、价格变化、股权分配 | 固定种子结果可复现 |
| 经济不变量 | 现金、冻结款、库存、船货、贷款、股权的增减 | 无凭空生成、无重复扣费和超卖 |
| 状态机 | 拍卖→经营→结算→总部；船队各阶段转换 | 无非法跳转、无重复结算 |
| 边界 | 0 资金、矿体耗尽、无买方额度、满仓、船失事、加载途中 | 不崩溃、不丢档、不锁死 |
| UI 自动/手动 | 拖拽取消、非法位置、确认前后、分辨率切换 | 预览不扣费，状态一致 |
| 视觉独立 | 动画跳过、低动效模式、场景卸载重载 | 纯视觉不修改经济结果 |
| 存档回归 | 本轮开始、进行中、结算后、竞拍中 | 幂等恢复，无重复奖励 |
| 长线平衡 | 20 回合/多种策略/不同 AI 风格/多种随机种子 | 无普遍必败、无无上限经济套利 |
| 玩家研究 | 首次操作、首次发射、首轮结算、第二轮意愿 | 提炼可执行的体验缺陷优先级 |

## 20.2 最少需要覆盖的异常情境

1. 矿区竞拍失败且现金被正确解冻。
2. 股权拍卖失败，股份百分比不变。
3. 采矿舱刚满时，生产停下而不是生成负库存。
4. 火箭在飞行中加载存档，不重复出发/到达。
5. 回收火箭检修中不可同时执行另一航次。
6. 一次性火箭重复出发时按规则消耗替换级费用。
7. 货物到港和市场出售同帧发生，仍不会超卖。
8. 卖方配额耗尽，未成交货物不消失。
9. 市场价格从高价跌落，不出现负价或无穷价。
10. D30 截止、合约到期和飞船抵港同时发生，结算次序唯一。
11. 快速重复点击购买/出售/竞价，命令按幂等键只执行一次。
12. 蓝图合法性在更换发动机后重新计算。
13. 低动效/跳过发射动画，运输时间与收益完全相同。
14. 无法负担矿区时，存在明确且有成本约束的恢复路径。
15. 旧版 V4 存档不被新 Frontier 战役直接覆盖。
16. 资金收益、利润、资产估值三种口径在结算中不重复计数。
17. 固定种子、同一操作序列、保存/加载前后得出同样结果。
18. 主场景缩放、平移、切屏不改变天体真实航程和资源数据。

## 20.3 试玩研究指标（目标，非市场事实）

- **引导**：首次玩家 2 分钟内理解下一步应做什么；若失败则定位 UI/提示问题。
- **理解**：完成一次销售后，能解释“为什么现金增加了这么多”。
- **反馈**：能区分一次性与可回收火箭的初期成本和长期成本。
- **操作**：主要操作不依赖嵌套菜单和精细像素点选。
- **重玩**：结束第一轮后，用户愿意尝试另一种经营策略；记录理由，不仅记录点击率。
- **性能**：目标平台在所承诺的画质档位达到性能预算，不能仅在开发电脑表现良好。

## 21.2 变更门槛

- **任何新增主机制**：至少说明“强化哪个设计支柱、影响哪三个系统、需要多少新 UI/美术、如何验收”，才可进入候选需求。
- **规则调整**：先更改 GDD 与平衡表版本，再提交实现代码；PR 中列出存档迁移影响。
- **视觉改动**：若不改变玩法，仍需验证场景辨识和性能；不得直接改写现金、库存或竞拍状态。
- **延期内容**：只记录接口和数据扩展点，不准为了将来可能的高级功能现在写大段空实现。

# 23. GDD 验收与项目立项结论

## 23.1 文档完成不等于游戏已经实现

本 GDD 用于锁定**目标玩法和工程交付边界**。它不能代替 UX 线框图、可运行的 Godot 场景、平衡数值表和真实玩家测试。因此即使所有章节齐全，也不应直接宣布“游戏开发完成”或“玩法验证成功”。

## 23.2 第一阶段开发启动条件

- [x] 架构负责人采用独立 Frontier 工程，不依赖旧 V4 模式。
- [ ] UX 负责人完成总部、矿区拍卖、太空采矿、火箭工坊、市场、结算六张低保真线框图。
- [ ] 数值负责人提供首局可获利的基本成本/价格模型，并覆盖一次性 vs 可回收火箭的至少两种最优场景。
- [ ] 玩法负责人确认一个完整的演示局：投标→扫描→部署→产矿→飞船→售出→结算。
- [ ] QA 负责人准备固定种子的库存/现金守恒、幂等和跨场景存档回归。
- [ ] 视觉负责人建立首个天体/采矿舱/火箭资产规格，明确动画可被跳过。

## 23.3 此阶段正式冻结的产品决策

1. 第一款游戏以“**短局策略经营 + 总部长期成长**”为产品骨架。
2. 太空探测、采矿部署和火箭运输必须发生在同一可理解的星域空间。
3. 原版《石油大亨》的完整**经济与进度功能族**均需在首发或明确扩展路线中有对应，不等于逐像素复刻原作。
4. 一次性与可回收火箭是核心经营差异；**拖拽组装纳入正式蓝图，但不阻塞核心切片**。
5. 首发战役要有土地/采矿权拍卖、股权竞拍、贷款、酒馆交易、科技升级和单局结算。
6. 经济真实性与视觉表现分离；任何动画失败、跳过、低动效都不改变结果。
7. 不再围绕旧版长线界面叠加；以独立短局工程为唯一当前产品开发线。

**配套文档状态**：六屏 UX V1.0 已完成（`docs/ux/UX_V1.0.md`），并在 Godot 中搭建了可交接的 Mock 交互原型；接下来须完成实际引擎运行验收，然后准备《初始数值与经济平衡表》与垂直切片。开发中每一次偏离本 GDD 的设计决策都需写入变更记录。
